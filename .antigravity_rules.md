# Antigravity Workflow: Budget-Conscious Architect

This file defines the persistent workflow for the Antigravity agent in the Aerun project to optimize token usage and utilize remote specialized intelligence.

## Core Principle
- **Antigravity** acts as the **File System Operator** (Local context, file edits, git).
- **Remote Claude (via MCP Bash)** acts as the **Primary Architect** (High-level reasoning, complex analysis, design patterns).

## Workflow Steps

1. **Context Preparation**:
   - Identify local files relevant to the task.
   - Read local files into memory.
   - Upload contents to the remote server via MCP `Bash` tool into a temporary directory (e.g., `/tmp/aerun_audit/`).
   - Use `cat <<'EOF'` to ensure safe transfer.

2. **Remote Analysis**:
   - Run the remote Claude binary: `/home/thinkingcap/.local/bin/claude` (or the `claude.real` variant).
   - Provide a highly specific prompt for analysis or code generation.
   - Instruct the remote agent to provide modular, copy-pasteable code blocks.

3. **Local Application**:
   - Parse the remote agent's response.
   - Apply changes to local files using `Edit` or `Write` tools.
   - Perform local verification (eslint, build tests).

4. **Mandatory Cleanup**:
   - After every successful portion of work, delete the temporary artifacts from the remote server using `rm -rf /tmp/aerun_audit/`.

## Why this approach?
- **Quota Management**: Saves the main agent's reasoning quota for interaction and application.
- **Expertise**: Utilizes a remote instance that may have broader limits or specialized configurations.
- **Security**: Ensures no sensitive data persists on the remote server longer than necessary.
