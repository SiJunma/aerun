# SECURITY.md — модель безопасности Aerun

> **Статус:** актуально (2026-11-02). Детали прав — `PROJECT_SPEC.md` §2; контракты — `API.md`.

## Принципы

1. **Deny-by-default.** Правила мутаций всех коллекций закрыты (superuser-only). Единственный путь изменения состояния — команды `/api/aerun/*` с разрешением роли через AccessResolver. Отсутствующая строка права → deny, не allow.
2. **Сервер — единственный арбитр.** Никакая UI-логика не считается проверкой права; всё проверяется на сервере (включая видимость скрытого контента и dice).
3. **Минимальная поверхность DTO.** Публичные профили/списки — whitelist-поля; `users.settings`, email и пр. через SDK недоступны.

## Слои проверок

- **Аутентификация:** PocketBase auth (пароль + Google OAuth2), токен в `Authorization`.
- **Права:** строковые ключи (`backend/internal/auth/permission.go`), роли в коллекции `roles`, rank-матрица для действий над чужими ролями.
- **Статус аккаунта:** гейт `requireLiveAccount` на всей группе; `pending` → `view_forum` + self-edit; `banned` → ничего.
- **Email verification gate:** контентные мутации требуют `verified=true` (исключения: гости, staff, pending-ответы в ЛС — см. `API.md` §3.2).
- **Root-роль:** передаётся только через `POST /admin/transfer-root` (root-роль + пароль вызывающего).
- **Идемпотентность:** защита от повторов мутаций (double-click, ретраи) через `Idempotency-Key`.

## Данные и секреты

- Конфигурация — только через окружение; `.env` на VPS mode 600, gitignored; `AERUN_ENCRYPTION_KEY` обязателен в production (ровно 32 байта).
- `pb_data/` (база, включая OAuth client secret внутри коллекций) — gitignored; не попадает в репозитории и публичные бэкапы.
- Пароли/хэши/токены никогда не возвращаются в ответах (в т.ч. регистрация).
- Почта: только через общий шаблон; test-эндпоинт ограничен собственным email аккаунта (анти-спам); mail guard не даёт «признаваться» в неотправленных письмах.

## Аудит и инциденты

- `audit_logs` фиксирует значимые действия (актор, роль, `request_id`) — единственный след hard-удалений.
- Инциденты разбираются по схеме из `.agent/rules/AGENTS.md` (правило «Deletion Must Settle Its Denormalized Copies»); отчёты живут в `markdowns/Archive/CLOSED_INCIDENT_*.md`.
- Сообщать об уязвимости — владельцу проекта (see `README.md`); публиковать в public issue до исправления нельзя.
