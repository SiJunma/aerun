# Концепция: Страница расширенного поиска по форуму (Advanced Forum Search)

**Статус:** Согласованный концепт с учётом фидбека (версия 2.0)  
**Стек:** Go 1.27 + PocketBase v0.40.4 + SQLite (FTS5) + React 18 + React-Bootstrap + Lucide-react  
**Референс интерфейса:** Классическая панель расширенного поиска форума (стиль MyBB / vBulletin)  
**Целевой файл:** `markdowns/CONCEPT_Search_Page.md`

---

## 1. Введение и цели

Главная цель — разработка полноценной страницы поиска (`/search`), сочетающей привычную для пользователей форумных движков (MyBB, phpBB, vBulletin) гибкость фильтрации с современным реактивным интерфейсом Aerun, строгим соблюдением прав доступа (RBAC), безопасностью скрытого контента (`[hide]`) и высокой производительностью на базе SQLite.

### Ключевые требования:
1. **Точное соответствие паттернам формы на референсном скриншоте:**
   - Поиск по ключевым словам (с разделителями-пробелами и логическими операторами `AND`, `OR`, `NOT`).
   - Поиск по автору сообщения/темы (аккаунты, маски персонажей, гости).
   - Выбор области поиска: выбор конкретного раздела или «Все разделы» (`All forums`).
   - Выбор объектов поиска: текст сообщения и заголовок темы, только текст, только заголовок.
   - Настройка отображения результатов: сортировка (по дате, автору, заголовку, разделу), направление сортировки (по возрастанию / убыванию) и формат выдачи (`Posts` / `Topics`).
2. **Подсветка искомых слов (Keyword Highlighting)** в заголовках и сниппетах найденного контента.
3. **Пагинация результатов поиска** (с отображением общего количества страниц и синхронизацией с URL).
4. **Контекстный поиск внутри конкретной темы (Search in Topic):**
   - Кнопка в теме, открывающая поиск с предзаполненной темой и режимом отображения сообщений.
5. **Строгая защита закрытого контента и тега `[hide]`:**
   - Проверка прав на просмотр категорий и тем.
   - **Учёт прав на просмотр содержимого тега `[hide]`:** если совпадение находится только внутри недоступного пользователю тега `[hide]`, пост **не выдаётся** в результатах поиска; скрытый текст никогда не утекает в сниппеты.
6. **Навигация и история поиска:**
   - Постоянная ссылка «Поиск» в верхнем навбаре.
   - История до 5 последних поисковых запросов в интерфейсе с быстрым префиллом всех параметров и кнопкой очистки.
7. **Профиль пользователя:**
   - В профиле не требуется отдельный переход в поиск: в существующий таб «Сообщения» добавляется конфигурация/фильтрация по темам автора.

Интерфейс формы поиска разделен на три логические секции, блок истории поиска и панель результатов. Вся страница оформляется в фирменной стилистике Aerun (с поддержкой светлой, тёмной и нейтральной тем оформления).

### Секция 1: Критерии поиска (Enter your search criteria)
- **Поле «Поиск по ключевым словам» (`Keyword Search`)**:
  - Текстовое поле ввода.
  - Поддерживает ключевые слова, фразы в кавычках (`"городской совет"`) и логические операторы:
    - `AND` (или пробел по умолчанию) — все слова должны присутствовать;
    - `OR` — хотя бы одно из слов;
    - `NOT` (или `-слово`) — исключить слово из результатов;
    - префиксный поиск со звездочкой (`маг*` найдет «магия», «магический»).
  - Валидация: минимальная длина терма — 2–3 символа (защита от перегрузки базы запросами по 1 символу).
- **Поле «Поиск по автору» (`Author Search`)**:
  - Текстовое поле с подсказками (автодополнение).
  - Учитывает доменную модель `AuthorRef`:
    - Имя основного пользователя (`users.nickname` / `users.username`);
    - Имя персонажа / игровой маски (`characters.name`);
    - Имя гостя (`posts.guest_display_name`).
  - Чекбокс «Точное совпадение имени» (по умолчанию выключен — поиск по подстроке).

### Секция 2: Где и что искать (Select where and what to search)
- **Выпадающий список «Раздел» (`Forum`)**:
  - Вариант по умолчанию: `Все разделы` (`All forums`).
  - Список категорий, сгруппированных по группам разделов (`category_groups`), доступных пользователю.
  - *Безопасность:* Список категорий генерируется строго с проверкой прав `canViewCategory`. Закрытые разделы не отображаются в списке тем, у кого нет к ним доступа.
- **Выпадающий список «Искать в» (`Search in`)**:
  - `В тексте сообщений и заголовках тем` (`Message text and topic subject`) — по умолчанию;
  - `Только в тексте сообщений` (`Message text only`);
  - `Только в заголовках тем` (`Topic subject only`).

### Секция 3: Параметры отображения результатов (Select how to view search results)
- **Сортировка («Sort by»)**:
  - `Дата публикации` (`Post time` / `created`) — по умолчанию;
  - `Релевантность` (`Relevance` / ранг BM25 из FTS5);
  - `Автор` (`Author`);
  - `Заголовок темы` (`Subject`);
  - `Раздел` (`Forum`).
- **Направление («Sort order»)**:
  - `По убыванию` (`Descending`) — от новых к старым / от Я к А;
  - `По возрастанию` (`Ascending`) — от старых к новым / от А к Я.
- **Формат отображения («Show results as»)**:
  - `Сообщения` (`Posts`) — детальные карточки найденных постов с фрагментом текста вокруг совпадений;
  - `Темы` (`Topics`) — компактный список тем форума, в которых найдены совпадения.

### Секция 4: История поиска (Search History)
- До 5 последних сохраненных запросов пользователя в `localStorage` (`aerun_search_history`).
- Отображение в виде интерактивных чипов/тегов над формой.
- **Клик по чипу:** немедленно префиллит все поля формы (ключевые слова, автор, раздел, режим отображения, сортировка) и отправляет запрос.
- **Управление:** кнопка `[✕]` на каждом чипе для удаления отдельного запроса + общая кнопка `[Очистить историю]`.

## 3. Режимы отображения результатов и подсветка (Highlighting)

### 3.1. Отображение в виде сообщений (`Show results as: Posts`)
Каждый результат оформляется как карточка сообщения:
1. **Шапка карточки:**
   - Хлебные крошки раздела: `[Категория] » [Название темы]` (кликабельные ссылки).
   - Заголовок темы с подсвеченными ключевыми словами (если совпадение было в названии).
   - Прямая ссылка на пост: `Перейти к сообщению »` (ведёт на `/topic/:topicId?post=:postId`).
2. **Блок автора (полноценный `AuthorRef`):**
   - Аватар (`ForumAuthorAvatar`).
   - Имя автора (`ForumAuthorName`): аккаунт, маска персонажа (`ForumCharacterBadge`), либо лейбл гостя.
   - Ролевой бейдж (`ForumRoleBadge`).
   - Дата публикации (`Timestamp`).
3. **Сниппет содержимого (Content Snippet):**
   - Длина: ~200–300 символов вокруг найденного слова.
   - **Очистка от BBCode:** перед формированием сниппета из текста удаляются тяжелые теги (`[quote]...[/quote]`, `[img]...[/img]`, `[spoiler]`, `[roll]`), чтобы верстка карточки не ломалась незакрытыми тегами или огромными цитатами.
   - **Защита тега `[hide]`:** содержимое тегов `[hide]`, к которым у зрителя нет доступа, полностью вырезается из сниппета (подробнее в §5.3).
   - **Подсветка:** найденные термы оборачиваются в `<mark class="search-highlight">слово</mark>`.
   - Если в посте несколько совпадений в разных местах — фрагменты разделяются многоточием `...`.

### 3.2. Отображение в виде тем (`Show results as: Topics`)
Каждый результат отображается в виде стандартной строки темы форума:
- Используется существующий компонент [TopicRow.jsx](file:///c:/Users/Alina/source/repos/SiJunma/aerun/src/components/common/TopicRow.jsx) с флагом `showCategory={true}`.
- В заголовке темы подсвечиваются искомые слова.
- Отображаются: статус темы (закреплена, закрыта), автор темы, количество ответов, информация о последнем сообщении и мини-пагинация.

### 3.3. Сквозная подсветка при переходе в тему (Deep-link Highlighting)
При клике на найденное сообщение пользователь переходит по ссылке вида:
```
/topic/{topicId}?post={postId}&highlight={encodedQuery}
```
- Компонент [TopicPage.jsx](file:///c:/Users/Alina/source/repos/SiJunma/aerun/src/pages/TopicPage.jsx) через серверный локатор постов `locatePost` мгновенно открывает нужную страницу и скроллит к целевому посту.
- В тексте целевого сообщения ключевые слова подсвечиваются желтым/акцентным маркером или карточка поста выделяется пульсирующей рамкой (с плавным угасанием через 3 секунды).

## 4. Пагинация и работа с URL (Pagination & Routing)

### 4.1. Пагинация
- Используется готовый проектный компонент [ForumPagination.jsx](file:///c:/Users/Alina/source/repos/SiJunma/aerun/src/components/common/ForumPagination.jsx).
- Количество элементов на страницу: берётся из настроек форума (`posts_per_page` для постов, `topics_per_page` для тем, по умолчанию 20).
- Сервер возвращает:
  ```json
  {

    "page": 2,
    "per_page": 20,
    "total_pages": 3,

  }
  ```
- В шапке результатов выводится статистика:
  *«Найдено 58 сообщений в 14 темах (Страница 2 из 3)»*.

### 4.2. Синхронизация с URL (Shareable Search URLs)
Все параметры поиска хранятся в query-параметрах URL:
```
/search?q=артефакт+дракона&author=Alden&forum=cat_general&in=both&sort=created&order=desc&as=posts&page=2
```
В случае поиска внутри конкретной темы:
```
/search?topic_id=top_abc123&q=зелье&as=posts&page=1
```
**Преимущества:**
- Корректная работа кнопок браузера «Назад» и «Вперед».
- Возможность скопировать ссылку и поделиться результатами поиска с другим участником.
- При перезагрузке страницы состояние фильтров и текущая страница не сбрасываются.

## 5. Бэкенд и безопасность (Go + SQLite + PocketBase)

### 5.1. Полнотекстовый поиск: SQLite FTS5
В PocketBase v0.40 используется движок SQLite (`modernc.org/sqlite`). В SQLite доступно два подхода:

| Критерий | Обычный `LIKE '%слово%'` | Полнотекстовый индекс `SQLite FTS5` (Рекомендуется) |
|---|---|---|
| **Регистронезависимость для кириллицы** | ❌ **Сломано:** стандартный SQLite `LIKE` не умеет в `case-insensitive` для символов за пределами ASCII без ICU расширения (`Привет` != `привет`). |  **Работает идеально:** токенизатор `unicode61` нативно приводит кириллицу и любые UTF-8 символы к единому регистру. |
| **Логические операторы (`AND`, `OR`, `NOT`)** | ❌ Требуется громоздкий самописный SQL-генератор с множеством условий и скобок. |  **Встроено в движок:** FTS5 парсит булевы выражения `слово1 AND (слово2 OR NOT слово3)`. |
| **Фразовый и префиксный поиск** | ⚠️ Только точные подстроки. |  `"точная фраза"`, `префикс*`, поиск по близости `NEAR(...)`. |
| **Сниппеты и подсветка** | ❌ Приходится скачивать весь текст поста (до 64 КБ) в Go и нарезать сниппеты вручную. |  Функция `snippet(posts_fts, 1, '<mark class="search-highlight">', '</mark>', '...', 25)` на стороне базы. |
| **Скорость на больших объемах** | ❌ `Full table scan` — на тысячах постов база читает каждую строку с диска. |  Инвертированный индекс (B-Tree), отклик за миллисекунды. |

#### Предлагаемая схема FTS5 (Миграция `17700000xx_posts_search_fts5.go`):
```sql
CREATE VIRTUAL TABLE IF NOT EXISTS posts_fts USING fts5(
    post_id UNINDEXED,
    topic_id UNINDEXED,
    category_id UNINDEXED,
    title,
    content,
    author_name,
    tokenize='unicode61 remove_diacritics 2'
);
```

#### Синхронизация FTS5:
В соответствии с проектными правилами (`AGENTS.md` — транзакционная целостность, удаление без остатков):
1. **При создании поста / темы:** запись в `posts_fts` добавляется внутри той же транзакции в Go-коде (`createPostHandler`, `createTopicHandler`).
2. **При редактировании:** обновляются поля `title` / `content`.
3. **При hard-delete:** строка удаляется из `posts_fts` в той же транзакции, где удаляется пост (`deleteTopicPosts`, `deletePostHandler`).
4. **Одноразовый бэкфилл:** миграция заполняет существующие опубликованные посты (`is_draft = false`).

### 5.2. Поиск по автору и модель `AuthorRef`
В проекте реализован строгий контракт `AuthorRef` (миграции `1770000000`–`1770000004`):
- Автор-пользователь: `author_id` ссылается на `users.id`.
- Маска / персонаж: `author_character_id` ссылается на `characters.id`.
- Гость: `author_kind = "guest"` с именем в `guest_display_name`.

**Алгоритм резолвинга автора на сервере:**
При передаче параметра `author="Рейстлин"`:
1. Ищем ID пользователей с похожим ником: `SELECT id FROM users WHERE nickname LIKE :q OR username LIKE :q`.
2. Ищем ID персонажей: `SELECT id FROM characters WHERE name LIKE :q`.
3. Формируем единое условие поиска:
   ```sql
   (author_id IN (:userIDs) OR author_character_id IN (:charIDs) OR guest_display_name LIKE :q)
   ```
Благодаря этому поиск по автору работает бесшовно для основных аккаунтов, ролевых масок и гостей.

### 5.3. Безопасность и RBAC (Access Control Invariants)

#### 5.3.1. Видимость разделов и тем (Категории)
1. **Серверный фильтр видимости:**
   Перед выполнением поискового запроса хендлер получает контекст вызывающего `acc := AccessFrom(e)`.
   Выбираются все категории форума и фильтруются функцией `canViewCategory(e.App, acc, cat.Id)`.
   Полученный список разрешенных `allowedCategoryIDs` передается в запрос:
   ```go
   if requestedCategory != "" {
       allowed, _ := canViewCategory(e.App, acc, requestedCategory)
       if !allowed {
           return validationError("category not accessible or not found")
       }
       scope = append(scope, dbx.HashExp{"category_id": requestedCategory})
   } else if requestedTopic != "" {
       allowed, _, _ := canViewTopic(e.App, acc, requestedTopic)
       if !allowed {
           return validationError("topic not accessible or not found")
       }
       scope = append(scope, dbx.HashExp{"topic_id": requestedTopic})
   } else {
       scope = append(scope, dbx.In("category_id", allowedCategoryIDs...))
   }
   ```
2. **Исключение черновиков:**
   Черновики (`is_draft = true`) строго исключаются из поисковой выдачи: `AND (is_draft = 0 OR is_draft IS NULL)`.
3. **Исключение отложенных scheduled постов**
  Касается "TODO_Scheduled posts concept.md" дока. Строго исключаются из поисковой выдачи.

#### 5.3.2. Защита содержимого тега `[hide]` (Hide Tag Security & Zero Leakage)
В Aerun тег `[hide]` имеет три варианта:
- `[hide]текст[/hide]` — скрыто для обычных пользователей (видят автор поста и администраторы/модераторы с правом `PermBypassHideTags`).
- `[hide=N]текст[/hide]` — требует наличия минимум `N` опубликованных сообщений для просмотра (либо автор, либо `PermBypassHideTags`).
- `[hide=@user_id]текст[/hide]` — адресный хайд: видят только автор поста, адресат `@user_id` и обладатели `PermBypassHideTags`.

**Критическое правило безопасности при поиске:**
> **Если искомое ключевое слово находится ТОЛЬКО внутри тега `[hide]`, к которому у текущего пользователя нет доступа — такой пост КАТЕГОРИЧЕСКИ ЗАПРЕЩЕНО возвращать в поисковой выдаче!**

Если бы это правило не соблюдалось, любой участник мог бы через перебор слов в поиске узнать, что скрыто в хайде (утечка конфиденциальных сведений, паролей, сюжетных спойлеров и личных сообщений).

**Механизм защиты на сервере (Go-слой):**
1. **Проверка прав вызывающего:**
   ```go
   canBypassHide := auth.Has(acc.Permissions, auth.PermBypassHideTags)
   viewerID := acc.UserID
   viewerPosts := acc.PostCount
   ```
2. **Если у пользователя есть `PermBypassHideTags` (администратор):**
   Ему доступен полный поиск по всему контенту без ограничений.
3. **Для обычных пользователей и гостей:**
   - При сопоставлении постов Go-слой валидирует совпадение через функцию:
     `sanitizeContentForViewer(post.Content, post.AuthorID, viewerID, viewerPosts, canBypassHide)`
   - Функция парсит теги `[hide]` в посте:
     - Для блоков `[hide]`, которые пользователь **не имеет права видеть**, их текст **вырезается** (заменяется на пустую строку или нейтральный маркер).
   - Если в результате очистки пост больше **не содержит** искомых слов (так как они были только внутри недоступного хайда) — пост **немедленно отсекается** из результатов и не попадает в `items` и общий `total`.
4. **Безопасность сниппетов:**
   При нарезке сниппета для поисковой выдачи закрытый текст хайда гарантированно отсутствует, предотвращая случайную утечку фрагментов скрытого содержимого.

## 6. Контракт API (`GET /api/aerun/search`)

### 6.1. Запрос
`GET /api/aerun/search`

| Параметр | Тип | Описание | Значение по умолчанию |
|---|---|---|---|
| `q` | string | Поисковая фраза (с поддержкой AND, OR, NOT) | `""` |
| `author` | string | Имя автора, персонажа или гостя | `""` |
| `exact_author` | bool (0/1) | Точное совпадение имени автора | `0` |
| `category_id` | string | ID категории форума (или пусто — все категории) | `""` |
| `topic_id` | string | ID конкретной темы (для поиска внутри темы) | `""` |
| `in` | string | Область поиска: `both`, `content`, `title` | `both` |
| `sort` | string | Поле сортировки: `created`, `relevance`, `author`, `title`, `category` | `created` |
| `order` | string | Порядок сортировки: `desc`, `asc` | `desc` |
| `as` | string | Формат выдачи: `posts` (сообщения) или `topics` (темы) | `posts` |
| `page` | int | Номер страницы (1-based) | `1` |
| `limit` | int | Количество результатов на страницу | `20` (clamp 1..50) |

## 7. Интеграция в экосистему форума и дополнительные фичи

### 7.1. Ссылка «Поиск» в навбаре форума
- В [Navbar.jsx](file:///c:/Users/Alina/source/repos/SiJunma/aerun/src/components/layout/Navbar.jsx) в основной блок навигации добавляется пункт:
  ```jsx
  <Nav.Link as={Link} to="/search" onClick={() => setExpanded(false)}>
    {t('nav.search', 'Поиск')}
  </Nav.Link>
  ```
- Пункт отображается рядом с «Пользователи» (`/members`) и доступен как авторизованным пользователям, так и гостям (`allowGuest: true`).

### 7.2. Кнопка «Поиск в теме» (Search in Topic)
- На странице темы [TopicPage.jsx](file:///c:/Users/Alina/source/repos/SiJunma/aerun/src/pages/TopicPage.jsx) в панели действий темы (рядом с кнопками «Подписаться» / «Новый ответ») добавляется кнопка:
  `<Search size={16} /> Поиск в теме`.
- Клик по кнопке выполняет переход на `/search?topic_id={topic.id}&as=posts`.
- Форма поиска открывается с предзаполненным ID темы и отображает плашку:
  *«Поиск в теме: [Название темы] [✕ Искать везде]»*.
- Позволяет мгновенно находить реплики, улики или сюжетные броски в огромных ролевых темах на 2000+ постов.

### 7.3. Профиль пользователя: расширение существующего таба «Сообщения»
- В [ProfilePage.jsx](file:///c:/Users/Alina/source/repos/SiJunma/aerun/src/pages/ProfilePage.jsx) уже имеется функциональный таб «Сообщения» (`/api/aerun/users/{id}/posts`) с фильтрацией по маскам.
- **Решение:** отдельный поиск из профиля не выносится. Вместо этого в существующий таб профиля добавляется переключатель/конфигурация:
  - `[ Сообщения автора ]` / `[ Темы автора ]`.
- Это сохраняет чистоту интерфейса профиля и закрывает потребность в просмотре тем конкретного участника без ухода на страницу глобального поиска.

### 7.4. История поиска (до 5 запросов)
- При выполнении успешного поиска параметры сохраняются в локальное хранилище браузера (`localStorage.setItem('aerun_search_history', ...)`).
- Максимум: 5 последних уникальных записей (вытеснение по принципу FIFO).
- Каждая запись хранит: `q`, `author`, `category_id`, `topic_id`, `in`, `as`, дату поиска.
- Пользователь может в 1 клик восстановить любой из прошлых запросов или очистить историю кнопкой «Очистить».
