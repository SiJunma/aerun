# Главная страница форума — спецификация структуры для темы

## Назначение документа

Этот документ является инструкцией для IDE-агента, который должен пересмотреть React-компоненты **главной страницы форума** и привести их DOM-структуру к стабильной системе классов и `id`, предназначенной для создания кастомных дизайнов/тем.

Структура должна быть построена так, чтобы:

1. внешний CSS темы мог полностью переоформлять форум без привязки к Bootstrap-классам;
2. структурные элементы имели стабильные семантические классы и `id`;
3. отдельные категории и форумы можно было стилизовать адресно;
4. состояния элементов (`new`, `unread`, `locked` и т. п.) можно было стилизовать через классы;
5. аналогичный подход можно было использовать позже для других страниц форума.

> **Важно:** это спецификация публичной DOM-структуры страницы. Bootstrap можно продолжать использовать внутри приложения, но Bootstrap-классы не должны быть единственным или основным API для кастомных тем.

---

# 1. Принципы для IDE-агента

При переработке компонентов:

- Сначала изучить существующие React-компоненты главной страницы и понять, какие данные и функции уже реализованы.
- Не менять бизнес-логику без необходимости.
- Не менять API данных без необходимости.
- Не удалять существующие функциональные возможности ради изменения HTML-структуры.
- Основная задача — изменить/добавить DOM-структуру и стабильные `class`/`id`.
- Не использовать порядковые классы вроде `.item1`, `.item2`, `.block3` для элементов, которые имеют собственную сущность.
- Не использовать Bootstrap-классы как публичный контракт темы.
- Не привязывать CSS к случайной структуре React-компонентов.
- Предпочитать семантические названия.
- `id` использовать для уникальных сущностей и крупных структурных контейнеров.
- `class` использовать для типов элементов и состояний.
- Если элемент является повторяемой сущностью, его `id` должен зависеть от его стабильного идентификатора из данных.

# 2. Страница

## `ForumIndex`

**Описание:** главная страница форума / список категорий и форумов.

Это верхнеуровневая страница, на которой пользователь видит:

- название/заголовок форума;
- навигацию;
- пользовательские ссылки;
- объявления, если они есть;
- статус пользователя/системную информацию;
- breadcrumbs;
- список категорий;
- список форумов внутри категорий;
- статистику;
- нижние breadcrumbs;
- информацию/ссылки форума в нижней части страницы.

Страница должна иметь один стабильный корневой контейнер:

```html
<div id="forum-wrapper">
    <div id="forum">
        ...
    </div>
</div>
```

# 3. Верхний уровень DOM

Рекомендуемая структура:

```text
#forum-wrapper
└── #forum
    ├── #forum-header
    │   ├── #forum-title
    │   ├── #forum-nav
    │   ├── #forum-user-links
    │   ├── #forum-announcement        (optional)
    │   └── #forum-status
    │
    ├── #forum-breadcrumbs-top
    │
    ├── #forum-main
    │   └── .forum-category
    │       └── .category-content
    │           └── .forum-item
    │
    ├── #forum-statistics
    ├── #forum-breadcrumbs-bottom
    └── #forum-about
```

Не обязательно буквально сохранять эту вложенность, если существующая архитектура React требует другого размещения. Но эти семантические области должны существовать и быть легко доступными для CSS темы.

# 4. Header

## `#forum-header`

Главный контейнер верхней части страницы.

### `#forum-title`

Название форума.

```html
<div id="forum-title">
    ...
</div>
```

Если внутри есть отдельные элементы для названия/логотипа, допускается:

```html
<div id="forum-title">
    <a class="forum-logo">...</a>
    <span class="forum-name">...</span>
</div>
```

Не делать `forum-logo` обязательным, если логотип сейчас отсутствует.

---

# 5. Навигация

## `#forum-nav`

Основная навигация.

Пример:

```html
<nav id="forum-nav">
    <a class="nav-link">...</a>
    <a class="nav-link">...</a>
</nav>
```

Если ссылки генерируются динамически, каждая ссылка может дополнительно иметь семантический класс:

```html
<a class="nav-link nav-home">...</a>
<a class="nav-link nav-search">...</a>
<a class="nav-link nav-members">...</a>
```

Не требуется копировать конкретные ссылки из старых форумных движков. Важна сама структурная область.

# 6. Пользовательские ссылки

## `#forum-user-links`

Ссылки, связанные с текущим пользователем.

Например:

- профиль;
- вход/выход;
- регистрация;
- личные сообщения;
- настройки;
- уведомления.

Структура:

```html
<div id="forum-user-links">
    ...
</div>
```

Внутренние классы должны быть семантическими, например:

```html
.user-profile
.user-login
.user-logout
.user-register
.user-messages
.user-notifications
```

Использовать только реально существующие элементы.

Если на странице есть объявление:

```html
<div id="forum-announcement">

</div>
```

Если объявления нет, контейнер не должен обязательно рендериться пустым.

# 8. Status

Общая системная/пользовательская информация.

Например:

```html
<div id="forum-status">
```

# 9. Breadcrumbs

## `#forum-breadcrumbs-top`

Breadcrumbs перед основным содержимым.

```html
<nav id="forum-breadcrumbs-top">
    ...
</nav>
```

## `#forum-breadcrumbs-bottom`

Breadcrumbs после основного содержимого.

```html
<nav id="forum-breadcrumbs-bottom">
    ...
</nav>
```

Внутренние классы:

```text
.breadcrumb
.breadcrumb-item
.breadcrumb-link
```

Если используется другая внутренняя структура, она допустима, если внешний контейнер остаётся стабильным.

# 10. Основное содержимое

## `#forum-main`

Главный контейнер списка категорий.

```html
<main id="forum-main">
    ...
</main>
```

Все категории главной страницы должны находиться внутри этой области.

# 11. Category

Каждая категория — отдельная сущность.

Для категории использовать одновременно:

```html
<section
    id="forum-category-{categoryId}"
    class="forum-category category-{categoryId}">
```

Например:

```html
<section
    id="forum-category-12"
    class="forum-category category-12">
```

### Зачем два значения

`.forum-category` позволяет написать общий CSS:

```css
.forum-category { ... }
```

`.category-12` позволяет теме адресно изменить конкретную категорию:

```css
.category-12 { ... }
```

`id` позволяет делать ещё более точные селекторы:

```css
#forum-category-12 { ... }
```

### Внутри категории

Рекомендуется:

```text
.forum-category
├── .category-header
│   └── .category-title
└── .category-content
    └── .forum-item
```

### `category-header`

```html
<header class="category-header">
    <h2 class="category-title">...</h2>
</header>
```

### `category-content`

```html
<div class="category-content">
    ...
</div>
```

---

# 12. Forum item

Каждый форум внутри категории — отдельная сущность.

Использовать:

```html
<article
    id="forum-item-{forumId}"
    class="forum-item forum-item-{forumId}">
```

Например:

```html
<article
    id="forum-item-25"
    class="forum-item forum-item-25">
```

Это особенно важно для кастомных тем.

Тема сможет написать:

```css
.forum-item { ... }
```

для всех форумов или:

```css
.forum-item-25 { ... }
```

для конкретного форума.

```text
.forum-item

├── .forum-info
│   ├── .forum-title
│   ├── .forum-description
│   ├── .forum-links
│   └── .forum-moderators

    ├── .last-post-link
```

# 14. Forum icon

## `.forum-icon`

Иконка состояния форума.

```html
<div class="forum-icon">
    ...
</div>
```

Не следует кодировать состояние только через разные изображения/иконки.

Состояние должно быть доступно через CSS-класс на `.forum-item`.

Например:

```html
<article class="forum-item forum-item-25 is-new">
```

### `.forum-description`

Описание форума.

```html
<div class="forum-description">
```

```html
<div class="forum-links">
```

# 16. Counters

Количество тем и сообщений должны иметь семантические классы:

```html
<div class="forum-topics">...</div>
<div class="forum-posts">...</div>
```

Не использовать:

```text
.item1
.item2
.tc2
.tc3
```

как единственный способ определить назначение элемента.

---

# 17. Last post

Последнее сообщение форума:

```html
<div class="forum-last-post">
    <div class="last-post-avatar">...</div>
    <a class="last-post-link">...</a>
    <div class="last-post-meta">
        <time class="last-post-date">...</time>
        <a class="last-post-author">...</a>
    </div>
</div>
```

Минимальный набор:

```text
.forum-last-post
.last-post-link
.last-post-date
.last-post-author
```

Avatar является optional.

# 18. Состояния

Состояния должны быть представлены отдельными классами.

Рекомендуемые классы:

```text
.is-active
.is-new
.is-unread
.is-locked
.is-sticky
.is-online
.is-hidden
.is-private
```

Использовать только те состояния, которые реально существуют в модели данных.

Пример:

```html
<article
    id="forum-item-25"
    class="forum-item forum-item-25 is-new">
```

Если одновременно несколько состояний:

```html
<article
    class="forum-item forum-item-25 is-new is-unread">
```

Не создавать десятки уникальных классов, если состояние можно выразить комбинацией базового класса и state-класса.

# 20. About / footer information

## `#forum-about`

Нижняя информационная область форума.

```html
<footer id="forum-about">
```

# 21. Data attributes

`data-*` можно использовать для данных, которые полезны теме или JavaScript, но не должны заменять классы.

Рекомендуется:

```html
data-category-id="12"
data-forum-id="25"
```

При необходимости можно использовать:

```html
data-forum-type="normal"
data-forum-status="locked"
```

Но визуальные состояния всё равно желательно отражать классами:

```html
class="forum-item is-locked"
```

То есть:

- `data-*` — данные;
- `class` — визуальные/логические состояния;
- `id` — уникальный адрес элемента.

# 24. Bootstrap

Bootstrap не нужно удалять из проекта.

Однако нельзя рассчитывать, что будущая тема будет стилизовать форум через:

```text
.container
.row
.col
.card
.nav
.btn
.table
.d-flex
```

Такие классы могут оставаться для внутренней layout-логики, но рядом должны присутствовать стабильные классы форума.

Например:

```html
<div class="row forum-item forum-item-25">
```

лучше, чем:

```html
<div class="row">
```

А для внешней темы основной селектор должен быть:

```css
.forum-item-25 { ... }
```

а не:

```css
.row { ... }
```

# 25. Что НЕ делать

Не переносить старую MyBB/Rusff HTML-структуру буквально.

Не нужно копировать:

- старые таблицы только ради совместимости;
- исторические классы без понятного назначения;
- классы, завязанные на конкретный способ отображения;
- технические классы Bootstrap как единственный API;
- классы вида `.item1`, `.item2`;
- классы, смысл которых невозможно определить без знания конкретной версии движка.

Цель — сохранить **идею стабильного theme API**, а не воспроизвести старый HTML.

# 26. Обратная совместимость и существующий код

Перед изменениями необходимо проверить:

1. какие React-компоненты сейчас отвечают за главную страницу;
2. какие props они получают;
3. какие данные используются для category/forum;
4. какие действия доступны пользователю;
5. какие Bootstrap-классы используются для layout;
6. какие CSS-файлы сейчас применяются;
7. есть ли существующие пользовательские темы или кастомный CSS;
8. нет ли JavaScript-кода, который ищет элементы по существующим `id`/`class`.

Если существующий `id`/`class` используется функциональным JavaScript-кодом, не удалять его без проверки.

Если существующий класс нужен только для Bootstrap/layout, его можно оставить и добавить поверх него новый стабильный класс.

# 27. Требование для будущих страниц

Эта спецификация относится только к:

# Forum Index / Главная страница форума

В дальнейшем аналогичный анализ должен быть проведён для других страниц, например:

```text
Forum Index
Forum View / список тем
Topic View / просмотр темы
Post View
Member List
Member Profile
Search
Private Messages
Login
Registration
User Settings
```

Каждая новая спецификация должна иметь:

1. название страницы;
2. назначение страницы;
3. верхнеуровневый DOM;
4. стабильные structural `id`;
5. повторяемые entity-классы;
6. state-классы;
7. внутренние семантические классы;
8. правила для `data-*`;
9. React component mapping;
10. что является публичным theme API;
11. что не следует копировать из старых MyBB/Rusff шаблонов.

Таким образом, со временем можно собрать единый **Forum Theme DOM Specification**, где каждая страница имеет отдельный раздел.

# 28. Итоговая задача IDE-агента

После анализа текущего кода:

1. Найти все React-компоненты, составляющие главную страницу форума.
2. Определить существующую структуру и не ломать её функциональность.
3. Перестроить DOM в соответствии с этой спецификацией.
4. Добавить стабильные `id`/`class` для theme API.
5. Добавить уникальные `id`/классы для категорий и форумов на основе их стабильных ID.
6. Добавить state-классы там, где соответствующие состояния существуют в данных.
7. Не использовать Bootstrap-классы как замену семантическим классам форума.
8. Не переписывать бизнес-логику без необходимости.
9. Не добавлять фиктивные элементы или состояния, которых нет в текущем приложении.
10. После изменений проверить, что:
   - главная страница визуально и функционально работает;
   - категории отображаются;
   - форумы отображаются;
   - ссылки работают;
   - counters отображаются;
   - last post отображается;
   - optional blocks не ломают layout;
   - CSS может обращаться к стабильным `forum-*` селекторам.

## Главный принцип

**React-компоненты могут меняться. Bootstrap может меняться. Внутренняя реализация может меняться. Но публичная DOM-структура для темы должна быть стабильной.**

Именно эта структура должна стать основой будущей системы кастомных дизайнов форума.
