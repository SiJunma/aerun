# DONE — Удаление темы: автору возвращён путь (тупик «используй меню темы»)

**Дата:** 2026-10-20  
**Статус:** `DONE` — правка клиента + исполняемые тесты (JS и Go), `npm test` — `CHAIN_OK`, целевые `go test` — PASS.

## 1. Симптом

Автор темы, захотевший её удалить, упирался в тупик:

1. Кнопка «Удалить» у **первого сообщения** отвечала отказом: *«Это первое сообщение темы. Удаление темы целиком доступно через меню темы.»*
2. «Меню темы» (выпадающий список «Управление темой») при этом показывало пункт **«Удалить тему»** только тем, у кого есть ключ `delete_others_topics`.

Ключ `delete_others_topics` есть только у admin/root — модераторам его **намеренно** не выдают (см. `backend/internal/auth/role.go`: «a moderator does not delete another account's topic»). То есть обычный автор отправлялся в меню, где пункта удаления для него не было. Ни один путь не работал.

## 2. Причина

Правило «кому показывать удаление темы» было **вплавлено в тело React-компонента** `TopicPage.jsx` (4000+ строк), а не вынесено в проверяемое место. Проверить его можно было только чтением исходника, а чтение не отличает правило, которое работает, от правила, которое просто написано.

При этом **сервер был не при чём**: `DELETE /topics/{id}` (backend/internal/platform/pocketbase/forum_topics.go, `deleteTopicHandler`) автора темы принимает и без каких-либо permission-ключей. Тупик был целиком клиентский.

## 3. Что сделано

### 3.1 Клиент

| Файл | Изменение |
|------|-----------|
| `src/utils/topic-delete.js` (новый) | Правило вынесено в чистый модуль без React: `resolveTopicOwnerId(topic)`, `canDeleteTopic({topic, user, hasPermission})`, `topicDeleteErrorText(err, lang)`. Правило **исполняемо** — его можно прогнать тестом. |
| `src/pages/TopicPage.jsx` | Удаление первого сообщения больше не отказывает: идёт через `DELETE /topics/{id}` (и **никогда** `DELETE /posts/{id}` — сервер отвечает на opening post 409 by design). Кнопка «Удалить тему» и кнопка «Удалить» у первого сообщения доступны автору. Отказы 409/403 названы своими текстами. Модалка удаления темы обёрнута в `try/catch`. Локальная копия правила удалена — остался один источник. |

**Ключевое решение — клиент не строже сервера.** Правило на клиенте отвечает на вопрос «существует ли действие», а не «разрешено ли оно»:

- автор своей темы → действие **есть** (сервер решит 200 или 409);
- посторонний → действия **нет** (сервер ответил бы 403) — иначе получилась бы зеркальная тупиковая кнопка, которая всегда отказывает;
- `delete_others_topics` → действие есть для любой темы.

## 5. Замечание (не в скоупе правки, но важно для владельца)

ADR `DONE_ADR_GUEST_AUTHOR_AND_READ_CURSOR_CONTRACT_2026-10-16.md` (строка 119–123) формулирует правило так: удаление темы «требует topic-permission (`delete_self_topic`/`delete_others_topics` по subject)». **Сервер на этом пути ключ `delete_self_topic` не проверяет**: авторам тема удаляется и без него (см. комментарий в `forum_topics.go`: «Allowed with NO permission… the author must always have a way to remove a thread that did not take off»).

Клиент теперь **зеркалит фактическое поведение сервера** — иначе он был бы строже сервера и вернул бы тупик в другой форме (кнопка скрыта, а сервер бы разрешил). Разводить ADR и сервер — отдельное решение владельца, поэтому здесь оно **не** менялось; правка фиксирует существующий контракт, а не создаёт новый.
