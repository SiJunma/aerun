## 1. Проблематика и цели

### Текущее поведение (UX Pain Points)
Сейчас в [TopicPage.jsx](file:///c:/Users/Alina/source/repos/SiJunma/aerun/src/pages/TopicPage.jsx) при нажатии кнопки **«Цитировать»** (`Quote`) под любым сообщением в теме (строки 3025–3033 для первого сообщения и 3607–3613 для остальных сообщений):
1. В стейт `replyContent` конкатенируется сгенерированный BB-код `[quote="#p<id>,t<topic>,<author>"]...[/quote]`.
2. Срабатывает вызов:
   ```javascript
   replyRef.current?.scrollIntoView({ behavior: 'smooth' });
   ```
3. Страница принудительно и резко скроллится в самый низ — к единственной форме ответа в футере темы.

### Чем это неудобно пользователю:
* **Срыв визуального контекста:** Читая сообщение в середине длинной страницы (например, пост #7 из 20) и нажимая «Цитировать», пользователь катапультируется на сотни пикселей вниз. Чтобы перечитать вопрос, на который он отвечает, или скопировать ещё одну мысль, ему приходится судорожно скроллить обратно наверх.
* **Невозможность пошагового набора ответа:** В ролевых, дискуссионных и аналитических темах типичный паттерн пользователя — читать тему последовательно сверху вниз, цитируя тезисы разных участников по очереди. При текущей схеме каждое нажатие цитаты выбрасывает пользователя из чтения.
* **Потеря фокуса:** Если в форме уже был набран текст, принудительный скролл дезориентирует.
* **Принудительный переход между страницами при публикации:** Если пользователь читал страницу 1 или 2 многостраничной темы и отправил ответ, текущий код (`TopicPage.jsx:1754`) насильно меняет `?page=targetPage` и выбрасывает пользователя на последнюю страницу, прерывая процесс чтения темы.
* **Принудительный скролл в подвал даже на текущей странице:** В текущем коде при отправке сообщения (`TopicPage.jsx:1769`) всегда вызывается `element.scrollIntoView()`. Если пользователь ответил на пост #4 в середине страницы, его снова насильно срывает в самый низ к новому посту, вместо того чтобы дать спокойно читать посты #5, #6 и т.д.

## 2. Предложенная идея автора и её декомпозиция

> **Суть предложения автора:**  
> 1. Вместо скролла страницы вниз — «выдергивать» форму ответа непосредственно под тот пост, на который пользователь нажал «Цитировать». При этом форма ответа остаётся **одной и той же (синглтоном)**: весь ранее набранный текст, вложения, выбранный персонаж и состояние драфта сохраняются, куда бы форма ни перемещалась.
> 2. **При отправке ответа:** форма очищается и **автоматически возвращается на дефолтное место (в подвал темы)**, чтобы не загромождать прочитанные посты.
> 3. **Если пост опубликовался на текущей странице:** страница **НЕ скроллится принудительно вниз**! Пользователь остаётся читать тему дальше, а в интерфейсе появляется интерактивный тоаст/подсказка со ссылкой-скроллом к новому сообщению (как в заголовках цитат).
> 4. **Если пост опубликовался на другой странице:** система не совершает резкий переход `?page=targetPage`, а показывает модалку с предложением перейти на последнюю страницу к сообщению или продолжить чтение текущей страницы.

### Архитектурные требования:
1. **Единый инстанс (Singleton State):** Форма не должна пересоздаваться или сбрасывать данные при переезде под другой пост. Введённый текст, черновик, выбранная маска персонажа, курсор и история `Undo/Redo` не должны теряться.
2. **Абсолютный запрет на принудительный скролл (Zero Forced Scrolling):** Ни при цитировании, ни при отправке ответа экран не должен самовольно срываться с текущего места чтения.
3. **Плавная анимация появления/перемещения:** Форма органично раскрывается под карточкой поста.
4. **Возможность возврата:** Пользователь должен иметь возможность в один клик отправить форму обратно в подвал страницы либо свернуть её.
5. **Контроль межстраничных переходов (Cross-Page Control):** Если опубликованный пост физически оказывается на другой странице пагинации, пользователь сам решает, переходить ли к нему сейчас или остаться на текущей странице.
6. **Автоматический возврат в дефолтное положение (Auto-Reset to Bottom on Submit):** При отправке поста форма очищается, инлайн-слот схлопывается, а компонент формы возвращается на штатное место внизу страницы (подвал темы).
7. **Интерактивная ссылка-скролл при публикации (Quote-like Scroll Affordance):** Переход к созданному посту всегда опционален и инициируется пользователем кликом по интерактивной ссылке с подсветкой целевого сообщения.

Мы проанализировали исходный запрос и современный опыт лучших платформ (Discourse, Flarum, GitHub Discussions, Linear). Ниже представлены 3 варианта: от прямой реализации идеи автора до гибридного решения.

### Вариант 1: Чистый динамический инлайн (Концепт Автора)

Форма ответа физически рендерится/перемещается в DOM прямо под контейнер сообщения, под которым была нажата кнопка «Цитировать» или «Ответить».

#### Макет интерфейса (Инлайн под постом):

```
┌─────────────────────────────────────────────────────────────────────────────┐
│ [Аватар]  Alden · 2 часа назад                                       #7 [⋮] │
│ Вчера в архивах гильдии магов мы обнаружили древний манускрипт...          │
│ ─────────────────────────────────────────────────────────────────────────── │
│                                      [👍 12]  [Репутация]  [💬 Цитировать]  │
└─────────────────────────────────────────────────────────────────────────────┘
  ▼  [ФОРМА ВЫДЕРНУТА ПОД ПОСТ #7]
┌─────────────────────────────────────────────────────────────────────────────┐
│ ┌─────────────────────────────────────────────────────────────────────────┐ │
│ │ 💬 Ответ на сообщение #7 от Alden           [⬇ В конец] [✕ Свернуть]    │ │
│ ├─────────────────────────────────────────────────────────────────────────┤ │
│ │ [Выбор маски: Элиас ▼]                               [Горячие клавиши ⌨]│ │
│ │ ┌─────────────────────────────────────────────────────────────────────┐ │ │
│ │ │ [B] [I] [U] [Quote] [Code] [Dice] ...                               │ │ │
│ │ │                                                                     │ │ │
│ │ │ [quote="#p7,t12,Alden"]Вчера в архивах гильдии...[/quote]           │ │ │
│ │ │ Согласен, но есть одна важная деталь...|                            │ │ │
│ │ └─────────────────────────────────────────────────────────────────────┘ │ │
│ │ [💾 Сохранить черновик]                            [ Отправить ответ ]  │ │
│ └─────────────────────────────────────────────────────────────────────────┘ │
└─────────────────────────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────────────────────────┐
│ [Аватар]  Kaelen · 1 час назад                                       #8 [⋮] │
│ Не стоит доверять этим свиткам без предварительной проверки...              │
└─────────────────────────────────────────────────────────────────────────────┘
```

#### Поведение и логика:
1. По клику на «Цитировать» на сообщении `Post A`:
   * В текст формы добавляется BB-код цитаты `Post A`.
   * Форма плавно разворачивается непосредственно под карточкой `Post A`.
   * Никакого резкого прыжка вниз! Фокус устанавливается в текстовое поле после цитаты.
2. Если форма **уже открыта** под `Post A`, а пользователь нажал «Цитировать» на `Post B`:
   * **Поведение:** Текст цитаты `Post B` аккуратно дописывается в существующий драфт (с новой строки).
   * Форма перемещается под `Post B` (с легкой плавной анимацией перемещения).
3. Кнопка **«⬇ В конец темы»**:
   * Возвращает форму в стандартное положение в футере темы под списком постов.
   * Текст и состояние полностью сохраняются.
4. Кнопка **«✕ Свернуть»**:
   * Сворачивает форму в компактную полоску под текущим постом: `[✏️ Ответ сохранен (черновик: 240 знаков) — Развернуть]`.
5. **При отправке ответа:**
   * Текст очищается, инлайн-слот под постом схлопывается, а форма возвращается на дефолтное место внизу темы.
   * Экран остаётся на месте, всплывает тоаст со ссылкой-скроллом к новому посту.

### Вариант 2: Плавающая шторка-композер (Sticky Bottom Drawer — стиль Discourse / Flarum)

Этот вариант решает классическую проблему чистого инлайна: **когда форма врезана под пост #3, вы не можете читать посты #8, #9, #10, не теряя форму из виду.**

#### Механика:
Вместо врезки внутрь потока постов, форма монтируется в **плавающую фиксированную панель** внизу окна браузера (`position: fixed; bottom: 0; left: 0; right: 0; z-index: 1040`).

```
├─────────────────────────────────────────────────────────────────────────────┤
│ [Аватар]  Kaelen · 1 час назад                                       #8 [⋮] │
```

* **Свободный скролл:** Вы можете скроллить всю страницу вверх и вниз, читать любые посты, листать цитаты, а редактор всегда перед глазами.
* **Мультицитирование:** Вы кликаете «Цитировать» на посте #3, потом скроллите до поста #12, кликаете «Цитировать» — цитаты моментально накапливаются в окне внизу без малейшего прыжка скролла!
* **Сворачивание в компактный Pill-бар:** Если нужно видеть весь экран, форма сворачивается в полоску высотой 40px внизу экрана:  
  `[ ✏️ Черновик ответа (2 цитаты, 310 знаков) ]  [Развернуть ▲]  [Отправить]`

Этот вариант объединяет непосредственную близость к посту (желание автора) с возможностью свободного чтения темы без потери редактора.

```
       │   Форма разворачивается ИНЛАЙН прямо под постом         │
       │   (Точно как в концепте автора)                         │
       └────────────────────────────┬────────────────────────────┘
                                    │
            ┌───────────────────────┴───────────────────────┐

                                    │
            ┌───────────────────────┴───────────────────────┐
```

#### Элементы управления в шапке формы Гибрида:
1. **Индикатор связи:** `Ответ на сообщение #N (@Username)`. Клик по номеру плавно центрирует пост.
2. **Кнопка «📌 В плавающее окно» (Dock to Bottom):** Переводит форму в режим Варианта 2 (шторка снизу), если предстоит большой анализ темы.
3. **Кнопка «⬇ В конец темы»:** Возвращает форму на классическое место в футер.
4. **Кнопка «✕ Свернуть»:** Прячет форму, оставляя компактный бейдж.

## 4. Дополнительные фичи и переработки (Enhancements)

### 4.1. Быстрое цитирование выделения (Quote Selection Tooltip)
* **Проблема:** Сейчас кнопка «Цитировать» забирает **весь** текст поста целиком. Если пост на 3000 знаков, пользователю приходится вручную стирать 90% чужого текста в поле ввода.
* **Решение:** Когда пользователь выделяет мышкой любую фразу внутри сообщения, рядом с курсором всплывает аккуратная мини-кнопка:
  ```
  ┌──────────────────────────────────────────────┐
  │ ...вчера мы обнаружили [древний манускрипт]  │
  │                              ┌─────────────┐ │
  │                              │ 💬 Цитата   │ │
  │                              └─────────────┘ │
  └──────────────────────────────────────────────┘
  ```
* При клике в форму ответа летит только выделенная фраза:
  `[quote="#p7,t12,Alden"]древний манускрипт[/quote]`.

### 4.2. Очистка от цитатных пирамид (Nested Quotes Strip)
В коде [TopicPage.jsx:3604](file:///c:/Users/Alina/source/repos/SiJunma/aerun/src/pages/TopicPage.jsx#L3604) уже есть функция `stripQuotes(content)`. При переносе формы в инлайн важно сохранить очистку вложенных цитат, чтобы форма не раздувалась от каскадных `[quote]...[quote]...[/quote][/quote]`.

### 4.3. Автосохранение черновика (Dual-Tier Autosave)
* **Tier 1 (LocalStorage):** Каждые 500 мс текст формы дебаунсится в ключ `aerun_topic_draft_<topicId>`. Если пользователь случайно закрыл вкладку или перешел на другую страницу пагинации — текст восстанавливается мгновенно.
* **Tier 2 (Server Draft API):** Существующая в Aerun кнопка «Сохранить черновик» отправляет состояние на бэкенд.

## 5. Межстраничная публикация и жизненный цикл формы

### 5.1. Проблема межстраничной отправки
Посты на форуме публикуются строго в конец темы в хронологическом порядке. Если:
1. Пользователь отвечает на сообщение, находясь на **архивной странице** темы (например, читает страницу 1 или 2 из 5);
2. Пользователь отвечает на последней странице, но лимит сообщений на страницу исчерпан (например, 20-й пост из 20), поэтому его ответ становится **первым сообщением на новой странице**;
3. Пока пользователь набирал текст, другие участники добавили новые ответы, и тема перешагнула на следующую страницу.

**В текущей версии [TopicPage.jsx:1754](file:///c:/Users/Alina/source/repos/SiJunma/aerun/src/pages/TopicPage.jsx#L1754):**
```javascript
if (targetPage !== currentPage) {
  setAlreadyJumped(false);
  setSearchParams({ page: targetPage }, {
    preventScrollReset: true,
    state: { pendingPostId: tempId }
  });
}
```
Принудительный вызов `setSearchParams({ page: targetPage })` мгновенно выдёргивает пользователя на последнюю страницу темы! Если человек увлеченно читал страницу 2 и захотел оставить короткую реплику на пост #15, его без предупреждения переносит на страницу 6 к своему посту, теряя место чтения.

---

### 5.2. Поведение при публикации на другой странице (Cross-Page Modal)

Когда ответ успешно отправлен, но `targetPage !== currentPage`:
1. **Никакого принудительного перехода!** Пользователь остаётся ровно на той странице и на той позиции скролла, где он находился.
2. Форма ответа инлайн очищается, закрывается и возвращается на дефолтное место в подвале текущей страницы.
3. На экране появляется диалоговая модалка `CrossPagePostModal` (в стилистике Aerun).

#### Макет модального окна публикации на другой странице:

```
┌────────────────────────────────────────────────────────────────────────┐
│  💬 Сообщение успешно опубликовано                                [✕]  │
├────────────────────────────────────────────────────────────────────────┤
│                                                                        │
│   Ваш ответ добавлен в тему.                                           │
│                                                                        │
│   Поскольку вы отвечали со страницы 2, ваше сообщение размещено        │
│   на последней странице темы (Страница 4, пост #61).                   │
│                                                                        │
```

#### Логика кнопок модалки:
1. **Кнопка «🚀 Перейти к сообщению»:**
   * Осуществляет переход: переключает пагинатор темы на `targetPage` (`setSearchParams({ page: targetPage, post: newPostId })`).
   * После загрузки постов плавно скроллит страницу к новому посту и подсвечивает его классом `.highlight-new-post`.
   * Модалка закрывается.
2. **Кнопка «Остаться на текущей странице» или крестик `[✕]`:**
   * Модалка закрывается.
   * Пользователь продолжает читать текущую страницу с того же самого места.
   * В верхнем правом углу экрана мягко всплывает информационный Toast:
     `✓ Сообщение опубликовано на стр. 4. [Перейти ↗]`.

### 5.3. Жизненный цикл формы и отмена принудительного скролла на текущей странице

Оставлять пустую форму под постом #7 после публикации недопустимо: она создаст ~300px пустого пространства посреди дискуссии и будет мешать читать следующие посты (#8, #9 и т.д.).

Принято правило: **при любой отправке поста форма автоматически возвращается на своё дефолтное место внизу страницы (подвал темы).**

#### Почему отменяется принудительный скролл даже на той же странице:
В текущей версии [TopicPage.jsx:1769](file:///c:/Users/Alina/source/repos/SiJunma/aerun/src/pages/TopicPage.jsx#L1769) при публикации на текущей странице срабатывал `element.scrollIntoView({ behavior: 'smooth' })`.  
Если пользователь читал пост #5 и ответил на него, его экран срывался вниз к посту #18. Это прямо противоречит задаче чтения темы без потери фокуса!

#### Новое поведение для той же страницы: Интерактивный Тоаст со ссылкой-скроллом
1. Экран **не совершает принудительного скролла**. Пользователь остаётся у того поста, где читал.
2. Форма инлайн закрывается и редоккается в подвал.
3. Новый пост оптимистично монтируется в конец списка постов текущей страницы.
4. Всплывает интерактивный тоаст:
   ```
   ┌─────────────────────────────────────────────────────────────┐
   │  ✓ Сообщение опубликовано!                                  │
   │  [ ↗ Перейти к сообщению ]                           [ ✕ ]  │
   └─────────────────────────────────────────────────────────────┘
   ```
5. **Механика ссылки-скролла (как в цитатах `BBCode.jsx:444-450`):**
   Клик по `[↗ Перейти к сообщению]` вызывает проверенный паттерн проекта:
   ```javascript
   const el = document.getElementById(`post-${newPostId}`);
   if (el) {
     el.scrollIntoView({ behavior: 'smooth', block: 'center' });
     el.classList.add('highlight-new-post');
     setTimeout(() => el.classList.remove('highlight-new-post'), 2000);
   }
   ```
   Если пользователь не кликает по ссылке, тоаст исчезает через 5 секунд, а пользователь продолжает спокойно читать посты #6, #7 и т.д.

## 6. Техническая реализация в React 18

### Главная проблема: Жизненный цикл компонентов при перемещении
Если мы попытаемся рендерить форму через простое условие:
```jsx
// ❌ ПЛОХОЙ ПОДХОД: вызовет unmount / remount формы при смене targetPostId!
{posts.map(post => (
  <div key={post.id}>
    <PostCard post={post} />
    {activeReplyPostId === post.id && <ReplyForm />}
  </div>
))}
{activeReplyPostId === null && <ReplyForm />}
```
**Почему это ломает компонент:**
1. `<RichEditor>` будет полностью размонтирован (`unmount`) и смонтирован заново (`mount`).
2. Сбросится DOM-состояние: позиция курсора, фокус, история отмены `Undo/Redo` в `textarea`, открытые диалоги палитры/смайлов/кубиков.
3. Произойдет мерцание интерфейса.

### Решение: Паттерн React Portal (`createPortal`)
Форма создаётся в дереве компонентов **в единственном экземпляре** в стабильном корневом контейнере, а её DOM-узел проецируется через `ReactDOM.createPortal` в слот нужного поста!

```jsx
// ✅ ПРАВИЛЬНЫЙ ПОДХОД: Форма НИКОГДА не размонтируется!

function TopicPage() {
  // Состояние размещения формы
  const [replyPlacement, setReplyPlacement] = useState({
    mode: 'bottom', // 'bottom' | 'inline' | 'floating'
    targetPostId: null,
    targetAuthor: null,
    targetPostNumber: null,
  });

  // Состояние модалки межстраничной публикации
  const [crossPageModal, setCrossPageModal] = useState({
    show: false,
    postId: null,
    targetPage: 1,
    currentPage: 1,
  });

  // Целевой DOM-элемент для портала
  const portalTargetNode = useMemo(() => {
    if (replyPlacement.mode === 'inline' && replyPlacement.targetPostId) {
      return document.getElementById(`inline-reply-slot-${replyPlacement.targetPostId}`);
    }
    if (replyPlacement.mode === 'floating') {
      return document.getElementById('floating-reply-drawer-slot');
    }
    return document.getElementById('bottom-reply-slot');
  }, [replyPlacement]);

  // Хелпер мягкого скролла к посту (как в ссылках цитат BBCode.jsx)
  const jumpToPostWithHighlight = (postId) => {
    const el = document.getElementById(`post-${postId}`);
    if (el) {
      el.scrollIntoView({ behavior: 'smooth', block: 'center' });
      el.classList.add('highlight-new-post');
      setTimeout(() => el.classList.remove('highlight-new-post'), 2000);
    }
  };

  // Обработчик отправки сообщения
  const submitReply = async () => {
    // 1. Очистка и сброс формы на дефолтное место
    setReplyContent('');
    localStorage.removeItem(`aerun_topic_draft_${id}`);
    setReplyPlacement({ mode: 'bottom', targetPostId: null });

    // 2. Расчет страниц
    const newTotalPosts = (topic?.posts_count || 0) + 1;
    const targetPage = Math.ceil(newTotalPosts / ITEMS_PER_PAGE) || 1;

    if (targetPage !== currentPage) {
      // Межстраничный ответ: остаемся на месте, показываем модалку
      setCrossPageModal({
        show: true,
        postId: tempId,
        targetPage,
        currentPage,
      });
    } else {
      // Ответ на текущей странице: оптимистичный рендер
      setPosts(prev => [...prev, optimisticPost]);

      // ВНИМАНИЕ: Принудительный scrollToPost() НЕ ВЫЗЫВАЕТСЯ!
      // Показываем интерактивный тоаст с возможностью перейти по желанию:
      showActionToast({
        title: lang === 'ru' ? 'Сообщение опубликовано' : 'Post published',
        actionLabel: lang === 'ru' ? 'Перейти к сообщению ↗' : 'Go to post ↗',
        onAction: () => jumpToPostWithHighlight(tempId),
        variant: 'success'
      });
    }
  };

  return (
    <div>
      {/* Список постов */}
      {posts.map(post => (
        <React.Fragment key={post.id}>
          <PostCard
            post={post}
            onQuote={(quoteText) => handleQuotePost(post, quoteText)}
          />
          {/* Пустой контейнер-слот под каждым постом */}
          <div id={`inline-reply-slot-${post.id}`} className="inline-reply-anchor" />
        </React.Fragment>
      ))}

      {/* Слот в самом низу страницы */}
      <div id="bottom-reply-slot" className="mt-5" />

      {/* Слот для плавающей шторки */}
      <div id="floating-reply-drawer-slot" className="floating-drawer-container" />

      {/* ЕДИНСТВЕННЫЙ ЭКЗЕМПЛЯР ФОРМЫ ЧЕРЕЗ ПОРТАЛ */}
      {portalTargetNode && ReactDOM.createPortal(
        <TopicReplyComposer
          topic={topic}
          placement={replyPlacement}
          onResetToBottom={() => setReplyPlacement({ mode: 'bottom', targetPostId: null })}
          onSwitchToFloating={() => setReplyPlacement(prev => ({ ...prev, mode: 'floating' }))}
          replyContent={replyContent}
          setReplyContent={setReplyContent}
          selectedCharacterId={selectedCharacterId}
          setSelectedCharacterId={setSelectedCharacterId}
          onSubmit={handleReply}
        />,
        portalTargetNode
      )}

      {/* Модалка публикации на другой странице */}
      <CrossPagePostModal
        show={crossPageModal.show}
        targetPage={crossPageModal.targetPage}
        currentPage={crossPageModal.currentPage}
        onNavigate={() => {
          setSearchParams({ page: crossPageModal.targetPage, post: crossPageModal.postId });
          setCrossPageModal(prev => ({ ...prev, show: false }));
        }}
        onClose={() => setCrossPageModal(prev => ({ ...prev, show: false }))}
      />
    </div>
  );
}
```

### Преимущества архитектуры на Portal:
1. **0 сбросов состояния:** Редактор физически не пересоздаётся.
2. **Мгновенная скорость:** Перемещение в DOM происходит синхронно за 1 кадр без лишних перерисовок React-дерева.
3. **Изоляция:** Код `TopicPage.jsx` очищается от 150 строк разметки формы, которая выносится в чистый компонент `TopicReplyComposer.jsx`.
