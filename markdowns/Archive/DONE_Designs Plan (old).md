# Реализация фичи "Кастомный дизайн"

Разработка функционала для создания и управления кастомными дизайнами (темами) форума, включая раздел "Гримерка" в панели администратора, предпросмотр и настройку доступности для пользователей.

## Одобренные решения (из комментариев)

- **Редактор кода**: Будут использоваться обычные текстовые поля (`textarea`) с моноширинным шрифтом и, возможно, опция загрузки файла.
- **Безопасность (XSS)**: Администраторы считаются доверенными лицами, скрипты внедряются как есть.
- **Отображение хедера**: Кастомный хедер будет **полностью заменять** стандартный Welcome Message (Banner).
- **Предпросмотр**: Реализуется через параметр `?preview_design=ID` в URL.
- **Отображение списка**: Дизайны в админке будут выводиться в виде **карточек** (Cards), а не таблицы.
- **Поля дизайна**: К дизайну добавлено поле "Forum Logo URL" и настройка "Показывать в списке выбора".
- **Логика деактивации/удаления**:
  - При деактивации появляется модалка: "Какой дизайн применить вместо деактивированного?".
  - Удалить активированный дизайн нельзя (появится просьба сначала его деактивировать).
- **Применение дизайна**:
  - Если переопределение запрещено (глобальная настройка), все принудительно видят дизайн по умолчанию, заданный в админке.
  - Если разрешено, пользователи могут выбирать дизайн из трех стандартных тем (они доступны всегда) и кастомных дизайнов, у которых включена галочка "Показывать в списке выбора".

### Client App & Injection

Логика применения выбранного дизайна на стороне клиента.

#### [NEW] `src/components/DesignProvider.jsx` (или `App.jsx`)
- Логика определения текущего дизайна:
  1. Если есть `?preview_design=ID` — используем его.
  2. Иначе, если глобально `allowUserCustomDesign === false` — используем `globalSettings.defaultDesignId`.
  3. Если `allowUserCustomDesign === true`, берем ID из профиля текущего пользователя (если он есть и дизайн существует).
  4. Если ничего не подошло или пользователь гость — используем `globalSettings.defaultDesignId`.
- Инжектит Custom CSS (`<style>`) и Custom JS (`<script>`) в `<head>`.
- Переопределяет `document.title` и `logoUrl` через контекст настроек (чтобы существующие компоненты Navbar использовали их).
- Переопределяет Welcome Message.

#### [MODIFY] `src/pages/ProfilePage.jsx`
- Если глобальная настройка `allowUserCustomDesign` включена:
  - Добавление выпадающего списка "Выбор дизайна" в настройки профиля.
  - Список формируется из трех базовых тем и кастомных дизайнов, где `showInList === true`.
