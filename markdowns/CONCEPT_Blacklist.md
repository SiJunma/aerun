# Концепция: Система Черного Списка и Скрытия Контента (Blacklist & Content Filters)

**Статус:** Согласованный концепт с учётом фидбека (версия 2.0)  
**Стек:** Go 1.24+ + PocketBase v0.40.4 + SQLite + React 18 + React-Bootstrap + Lucide-react  
**Целевой файл:** `markdowns/CONCEPT_Blacklist.md`  

---

## 1. Введение и разделение понятий

Главная цель системы — предоставить пользователю форума Aerun гибкие и удобные инструменты управления своим информационным полем.

Система разделяется на два взаимосвязанных, но смыслово различных механизма:

```
┌─────────────────────────────────────────────────────────────────────────────────┐
│              ПЕРСОНАЛЬНОЕ УПРАВЛЕНИЕ КОНТЕНТОМ (CONTENT FILTERS)                │
├────────────────────────────────────────┬────────────────────────────────────────┤
│     1. ЧЕРНЫЙ СПИСОК (ЧС / BLACKLIST)  │   2. СКРЫТИЕ НЕИНТЕРЕСНОГО (MUTE/HIDE) │
│           [Межличностный фильтр]       │          [Контентный фильтр]           │
├────────────────────────────────────────┼────────────────────────────────────────┤
│ • Блокировка токсичных пользователей   │ • Скрытие неинтересных тем             │
│ • Сворачивание их постов в темах       │ • Скрытие неинтересных разделов        │
│ • Сворачивание цитат НА их посты       │ • Исключение из главной страницы       │
│ • Запрет входящих Личных Сообщений     │ • Исключение из «Активных тем»         │
│ • Глушение уведомлений и упоминаний    │ • Исключение из «Новых ответов»        │
└────────────────────────────────────────┴────────────────────────────────────────┘
```

1. **Черный список участников (ЧС / Blacklist)** — защитная межличностная блокировка:
   - Скрывает сообщения заблокированного пользователя в темах (в стиле соцсетей — плашкой, сохраняя пагинацию).
   - Сворачивает цитаты **НА посты** заблокированного пользователя в сообщениях других (не заблокированных) участников.
   - Запрещает отправку входящих Личных Сообщений (ЛС) от заблокированного автора.
   - Глушит уведомления (ответы, цитаты, теги `@ник`).
   - Первое сообщение темы (OP) **не скрывается**, сохраняя контекст дискуссии.
2. **Скрытие неинтересных тем и разделов (Hidden Topics & Categories)** — персональная настройка комфортной ленты форума:
   - Пользователь скрывает темы или разделы, которые ему не интересны (например, оффтоп-флудилку, спойлерную ветку или неактуальный ролевой регион).
   - **Разделы не показываются на главной странице** форума (без навязчивых меток «ЧС»).
   - Темы из скрытых разделов и персонально скрытые темы **не отображаются в лентах «Активные темы» и «Новые ответы»**, а также не накручивают глобальные счетчики непрочитанного.

## 2. Сценарии использования и UX-флоу

### Сценарий A: Межличностная блокировка (Черный список)
1. **Добавление в ЧС:** Алиса заходит в профиль Боба (`/profile/:bob_id`) и нажимает кнопку `[ 🚫 В черный список ]`.
2. **Действие системы:**
   - Боб заносится в ЧС Алисы (`target_type: 'user'`).
   - Боб больше не может писать Алисе в ЛС (при попытке отправить сообщение сервер возвращает `403 Forbidden`).
   - Уведомления об упоминаниях Алисы Бобом (`@Alina`) и его ответах не доставляются.

### Сценарий B: Просмотр темы с постами из ЧС и цитатами на них
1. Алиса открывает тему `/topic/45`.
2. **Первый пост темы (OP):** Написан Бобом. **Не скрывается!** Алиса видит стартовое сообщение полностью, понимая правила и тему обсуждения. Сверху выводится нейтральный бейдж: `[ℹ️ Автор темы находится в вашем черном списке]`.
3. **Обычный пост Боба в середине темы:** Отображается в виде компактной плашки-заглушки:  
   `[ #14  21.10.2026, 14:32  🚫 Сообщение от Bob_Wizard скрыто.  (Развернуть сообщение ▾) ]`  
   Пагинация (20 постов на странице), ссылки `#post-xxx` и порядковые номера не сбиваются.
4. **Цитата НА пост Боба в посте другого участника (Чарли):**  
   Чарли не находится в ЧС у Алисы. Чарли процитировал пост Боба:
   - Собственный текст Чарли виден полностью.
   - Блок цитаты, ссылающийся на пост Боба, автоматически сворачивается в плашку с предупреждением:  
     `[ ⚠️ Цитата на сообщение Bob_Wizard свернута.  (Показать цитату ▾) ]`
   - При клике на «Показать цитату ▾» блок разворачивается прямо на месте.

### Сценарий C: Скрытие неинтересных тем и разделов
1. **Скрытие раздела:** На главной странице (`/`) Алиса не интересуется разделом «Таверна и флуд». Она нажимает иконку `[EyeOff] Скрыть раздел`.
   - Раздел перестает загромождать главную страницу форума.
   - Внизу блока категорий появляется ненавязчивая строка: `Скрыто разделов: 1 (Показать)`.
2. **Скрытие темы:** В списке тем раздела или внутри темы Алиса нажимает `[EyeOff] Скрыть тему` на теме «Спор о футболе».
   - Эта тема больше не выводится в лентах `/active-topics` (Активные темы) и `/new-replies` (Новые ответы).

## 3. Интерфейсные решения и Wireframes (UI/UX)

### 3.1. Кнопка ЧС в профиле участника (`ProfilePage.jsx`)

Кнопка размещается в левом сайдбаре профиля рядом с кнопкой «Написать»:

Комментарий автора: Нет, кнопка должна быть менее акцентной и не занимать такую же важность, как кнопка ЛС. Надо сделать ее меньше и вынести в отдельное место, чтобы исключить случайное нажатие.

```

│              [ Аватар 72x72 ]                 │
│                 Bob_Wizard                    │
│            «Маг стихии шторма»                │

│  ┌───────────────────┐  ┌──────────────────┐  │
│  │ ✉ Написать (ЛС)  │  │🚫 В черный список│  │
│  └───────────────────┘  └──────────────────┘  │

│  Сообщений: 142               Репутация: +48  │
│  Роль: Игрок                                  │
└───────────────────────────────────────────────┘
```

#### Поведение и состояния:
- **Не в ЧС:** `<Button variant="outline-danger" size="sm">` с иконкой `<UserX size={14} />` и надписью «В черный список».
- **Уже в ЧС:** `<Button variant="danger" size="sm">` с надписью «В черном списке» (при наведении плавно меняется на «Убрать из ЧС»).
- **Свой профиль (`isOwn`):** Кнопка не отображается.
- **Иммунитет администрации (Staff Immunity):** Для администраторов и супермодераторов кнопка неактивна (disabled) с понятным тултипом: *«Администраторов и модераторов нельзя добавить в черный список»*.

Если тему создал пользователь из ЧС:
- **Сообщение НЕ скрывается** и отображается в полном объеме, чтобы посетитель понимал суть темы, правила опроса или ролевого квеста.
- В шапке сообщения отображается деликатная плашка:

```

│ ℹ️ Автор этой темы (Bob_Wizard) находится в вашем черном списке.             │

├───────────────────┬──────────────────────────────────────────────────────────┤
│ [Аватар Bob]      │ [Заголовок темы: Поход в катакомбы]                      │
│ Bob_Wizard        │ Сбор группы назначен на субботу. Вход через старые врата...│
```

### 3.4. Сворачивание цитат НА посты заблокированного автора (`BBCode.jsx`)

Если добросовестный участник (Чарли) цитирует пост заблокированного пользователя (Боба):

```
┌──────────────────────────────────────────────────────────────────────────────┐
│ Автор: Charlie                                                   #15, 14:40  │
├──────────────────────────────────────────────────────────────────────────────┤
│ Я категорически не согласен с этим утверждением:                             │
│                                                                              │
│ ┌──────────────────────────────────────────────────────────────────────────┐ │
│ │ ⚠️ Цитата на сообщение Bob_Wizard свернута.        [ Показать цитату ▾ ] │ │
│ └──────────────────────────────────────────────────────────────────────────┘ │
│                                                                              │
│ По правилам третьей редакции этот заклинательный круг работает иначе!        │
└──────────────────────────────────────────────────────────────────────────────┘
```

#### Механизм распознавания в `BBCode.jsx`:
- Формат цитаты Aerun: `[quote="#p<postId>,t<topicId>,<authorName>"]...[/quote]`.
- Парсер проверяет:
  1. Связан ли ID цитируемого поста (`#p<postId>`) с автором из ЧС;
  2. Либо совпадает ли `authorName` с никнеймом или именем персонажа из ЧС.
- Если автор цитируемого поста в ЧС — цитата рендерится свернутой с кнопкой «Показать цитату ▾».
- Собственный текст автора сообщения (Чарли) **остается открытым и легко читаемым**.

### 3.5. Скрытие неинтересных тем (Topic Hide / Mute)

#### А. Интерфейс скрытия:
- **Внутри темы (`TopicPage.jsx`):** Кнопка `[ 👁️‍🗨️ Скрыть тему ]` в шапке темы.
- **В списке тем раздела (`CategoryPage.jsx`, `TopicRow.jsx`):** Иконка `[EyeOff]` в строке темы при наведении.

#### Б. Поведение темы после скрытия:
- **В ленте «Новые ответы» (`/new-replies`):** Тема **полностью исключается** из выдачи.
- **В ленте «Активные темы» (`/active-topics`):** Тема **полностью исключается** из выдачи.
- **В списке тем раздела (`CategoryPage.jsx`):** Отображается компактной нейтральной строкой:
  ```text
  ┌────────────────────────────────────────────────────────────────────────────┐
  │ [👁️‍🗨️] Скрытая тема: «Спорные вопросы правил магии»   [ Показать ] [ Вернуть ] │
  └────────────────────────────────────────────────────────────────────────────┘
  ```
  *(В персональных настройках пользователь может включить режим «Полностью исключать из списков разделов»).*

### 3.6. Скрытие неинтересных разделов (Category Hide / Mute)

Скрытие раздела — это **инструмент кастомизации витрины форума под интересы конкретного игрока**. Здесь не используются ярлыки «ЧС» или карательные плашки.

#### А. Интерфейс скрытия:
- **На главной странице (`MainPage.jsx`):** Иконка `[EyeOff]` при наведении на строку категории с подсказкой *«Скрыть раздел с главной»*.
- **Внутри раздела (`CategoryPage.jsx`):** Кнопка `[ 👁️‍🗨️ Скрыть раздел ]` в верхней панели рядом с «Создать тему».

#### Б. Отображение на главной странице (`MainPage.jsx`):
Скрытый раздел **не показывается в основной таблице категорий**, не отвлекая внимание пользователя.  
Внизу соответствующей группы разделов (или в подвале таблицы) выводится аккуратная строчка:
```text
  [ 📁 Скрытых разделов: 1 (Таверна и флуд) — Нажмите, чтобы показать ]
```
При нажатии раздел можно временно раскрыть или нажать «Вернуть на главную».

#### В. Системный эффект скрытия раздела:
- Темы из скрытого раздела **автоматически исключаются**:
  - из глобального списка `/active-topics` (Активные темы);
  - из глобального списка `/new-replies` (Новые ответы);
  - из счетчика непрочитанных тем в навбаре (`unreadTopicsCount`);
  - из виджета «Последние сообщения» в статистике форума.

## 4. Архитектура данных (SQLite & PocketBase)

### 4.1. Коллекция `user_blocks`

Для хранения всех типов персональной фильтрации используется единая компактная таблица:

| Поле | Тип | Обязательное | Описание |
| :--- | :--- | :---: | :--- |
| `id` | Text (15) | Да | Идентификатор PocketBase |
| `user_id` | Text (15) | Да | Владелец настройки (`users.id`) |
| `target_type` | Text (16) | Да | Тип: `'user'` (ЧС), `'topic'` (тема), `'category'` (раздел) |
| `target_id` | Text (15) | Да | ID целевого пользователя, темы или категории |
| `reason` | Text (255) | Нет | Личная заметка (видна только владельцу) |
| `created` | Autodate | Да | Дата добавления |
| `updated` | Autodate | Да | Дата обновления |

### 4.2. Индексы и ограничения целостности

1. `UNIQUE(user_id, target_type, target_id)` — гарантирует отсутствие дублей.
2. `idx_blocks_user_type_created (user_id, target_type, created)` — быстрая выборка фильтров пользователя за O(log N).
3. `idx_blocks_reverse (target_type, target_id, user_id)` — быстрый reverse-lookup для проверки: «Заблокировал ли получатель ЛС отправителя?».

### 4.3. PocketBase миграция (Go)

```go
package migrations

import (
	"github.com/pocketbase/pocketbase/core"
	m "github.com/pocketbase/pocketbase/migrations"
)

const userBlocksCollectionTable = "user_blocks"

func init() {
	m.Register(func(app core.App) error {
		col := core.NewBaseCollection(userBlocksCollectionTable)

		col.Fields.Add(
			&core.AutodateField{Name: "created", OnCreate: true},
			&core.AutodateField{Name: "updated", OnCreate: true, OnUpdate: true},
			&core.TextField{Name: "user_id", Required: true, Max: 15},
			&core.TextField{Name: "target_type", Required: true, Max: 16},
			&core.TextField{Name: "target_id", Required: true, Max: 15},
			&core.TextField{Name: "reason", Max: 255},
		)

		// Правило безопасности Aerun: блокируем прямой доступ из браузера через SDK
		lockBrowserRules(col)

		col.AddIndex("idx_blocks_unique", true, "user_id, target_type, target_id", "")
		col.AddIndex("idx_blocks_user_type", false, "user_id, target_type, created, id", "")
		col.AddIndex("idx_blocks_target_lookup", false, "target_type, target_id, user_id", "")

		return app.Save(col)
	}, func(app core.App) error {
		col, err := app.FindCollectionByNameOrId(userBlocksCollectionTable)
		if err == nil && col != nil {
			return app.Delete(col)
		}
		return nil
	})
}
```

## 5. Backend API и Командный слой (Go Engine)

### 5.1. Маршруты в `run.go`

```go
group.GET("/me/blacklist", listMyBlacklistHandler)
group.POST("/me/blacklist", addToBlacklistHandler).BindFunc(enforceIdempotency)
group.DELETE("/me/blacklist/{id}", removeFromBlacklistHandler).BindFunc(enforceIdempotency)
group.DELETE("/me/blacklist/{target_type}/{target_id}", removeTargetFromBlacklistHandler).BindFunc(enforceIdempotency)
```

### 5.2. Бизнес-логика обработчиков

1. **Запрет блокировки самого себя:**
   ```go
   if req.TargetType == "user" && req.TargetID == e.Auth.Id {
       return badRequest("cannot blacklist yourself")
   }
   ```
2. **Иммунитет администрации (Staff Immunity):**
   ```go
   if req.TargetType == "user" {
       targetUser, err := txApp.FindRecordById("users", req.TargetID)
       if err == nil && isStaffRole(targetUser.GetString("role_id")) {
           return forbiddenError("administrators and moderators cannot be blacklisted")
       }
   }
   ```
3. **Блокировка отправки ЛС (`sendDMMessageHandler`, `createDMHandler`):**
   ```go
   // Если получатель занес отправителя в ЧС — блокируем отправку
   isBlocked, err := checkIsBlocked(txApp, recipientUserID, "user", senderUserID)
   if err != nil {
       return internalError("failed to verify blacklist", err)
   }
   if isBlocked {
       return forbiddenError("this user does not accept direct messages from you")
   }
   ```
4. **Глушение уведомлений:**
   При генерации событий цитирования (`quote`) или упоминания (`mention`):
   ```go
   if isUserBlacklisted(txApp, recipientID, authorID) {
       // Пропускаем создание записи в notifications
       continue
   }
   ```
5. **Игровые маски персонажей:**
   Проверка ЧС в постах и цитатах всегда проверяет `author.user_id` (базовый аккаунт владельца). Смена маски персонажа не позволяет обойти блокировку.
