# CONCEPT: Кастомный HTML-футер форума

Ветка: `main`. Статус: концепт для исполнителя (задача на реализацию, не отчёт).

## 1. Цель

Дать администратору возможность задавать произвольный HTML-футер форума —
блок под основным содержимым страниц, рядом с существующей строкой копирайта.
Паттерн повторяет существующий кастомный HTML-баннер (`welcomeMessage`):
то же хранение, та же санитизация, то же место редактирования в админке.

## 2. Текущее состояние (проверено по коду ветки `main`)

- Футер жёстко зашит в `src/components/layout/Layout.jsx`: `<footer
  id="forum-about" className="forum-about footer-custom py-2 text-center">`
  содержит только строку копирайта с годом и названием форума
  (`activeDesign?.forumTitle` либо `settings.forumName`). Слота под
  произвольный HTML нет.
- Образец для подражания — баннер приветствия в том же файле: `settings?
  .welcomeMessage` (или `activeDesign.welcomeMessage`) проходит через
  `sanitizeHtml()` из `src/utils/text.js` и рендерится через
  `dangerouslySetInnerHTML` в `<div id="forum-announcement">`, только на
  главной (`location.pathname === '/'`).
- Хранение брендинга — двуязычный JSON, а не две колонки
  (`backend/internal/migrations/1768800000_global_settings_server_side.go`):
  `forumName` и `welcomeMessage` — карты `{en, ru}`, сиды `forum_name` /
  `welcome_message`; в Go-структуре настроек
  (`backend/internal/platform/pocketbase/global_settings.go`)
  `WelcomeMessage map[string]any \`json:"welcomeMessage"\``. Выбор языка на
  фронтенде: `settings.welcomeMessage[lang] || settings.welcomeMessage.en
  || ''`.
- Редактирование брендинга — в админке, карточка общих настроек
  (`GeneralSettingsCard`, PATCH `{ forumName, welcomeMessage }`).
- Санитизация (`sanitizeHtml`, `src/utils/text.js`): разрешены теги `div`,
  `span`, `p`, `br`, `hr`, `b`, `strong`, `i`, `em`, `u`, `s`, `del`,
  `small`, `sub`, `sup`, `a`, `img`, `table`/`thead`/`tbody`/`tfoot`/`tr`/
  `td`/`th`, `ul`, `ol`, `li`, `dl`, `dt`, `dd`, `h1`–`h6`, `blockquote`,
  `pre`, `code`, `q`, `cite`, `section`, `article`, `header`, `footer`,
  `main`, `figure`, `figcaption`; атрибуты `class`, `id`, `href`, `src`,
  `alt`, `title`, `width`, `height`, `colspan`, `rowspan`, `type`, `style`.
  Запрещены `script`, `style`, `iframe`, `svg`, все `on*`-атрибуты;
  неизвестный тег удаляется вместе с поддеревом; `src`/`href` — только
  относительные, `http(s)` либо `data:image/(png|jpeg|webp|gif);base64`.
  При ошибке парсинга возвращается пустая строка, а не исходник.

## 3. Решения (принятые по умолчанию; спорные — на усмотрение заказчика)

1. **Размещение:** кастомный HTML рендерится внутри существующего
   `<footer id="forum-about">`, над строкой копирайта. Строка копирайта
   сохраняется всегда — футер дополняет её, а не заменяет.
2. **Языки:** как у `welcomeMessage` — двуязычная карта `{en, ru}`.
   Пустое значение на текущем языке → fallback на `en` → пусто.
3. **Хранение:** только в глобальных настройках форума (`forum_settings`),
   без переопределения на уровне дизайна. Переопределение через
   `activeDesign` — необязательное расширение, по умолчанию не делать.
4. **Видимость:** на всех страницах (футер — глобальный chrome), в отличие
   от баннера, который показывается только на `/`.
5. **Пустое значение:** футер побайтово как сейчас — никакого пустого блока,
   никаких лишних отступов.

## 4. Реализация

### 4.1. Бэкенд (Go + PocketBase)

1. Миграция: новый ключ глобальных настроек `custom_footer_html` —
   двуязычный JSON, сид — пустая карта (аналогично `welcome_message`).
2. В `global_settings.go`: поле `CustomFooterHtml map[string]any
   \`json:"customFooterHtml"\`` рядом с `WelcomeMessage`; включить его в
   чтение настроек и в валидацию PATCH (только админ; длина — тот же лимит,
   что у `welcomeMessage`, либо явно заданный в задаче).
3. Серверная санитизация не требуется: HTML хранится как есть, чистится
   только на рендере тем же `sanitizeHtml`, что и баннер. Если сервер уже
   валидирует `welcomeMessage` — применить ту же проверку к новому полю.

### 4.2. Админка

1. В карточку общих настроек (`GeneralSettingsCard`, вкладка общих настроек
   админки) добавить поле «HTML-футер»: два текстовых поля (EN / RU) либо
   одно поле с переключателем языка — как сделано для `welcomeMessage` в
   этой же карточке.
2. Рядом с полем — живой предпросмотр: рендер введённого HTML через тот же
   санитизатор, что на фронтенде, чтобы администратор видел, что именно
   переживёт чистку.
3. Сохранение — тем же PATCH, что и остальные поля карточки, с добавлением
   `customFooterHtml`. Пустое значение должно именно очищать футер, а не
   игнорироваться.
4. Новые i18n-ключи (EN + RU) для подписи поля и подсказки; тексты — без
   технических деталей, одна строка о том, что разрешён безопасный HTML.

### 4.3. Фронтенд (`Layout.jsx`)

1. По образцу `sanitizedBanner`: `useMemo` `sanitizedFooter` — взять
   `settings?.customFooterHtml`, выбрать язык (`[lang] || .en || ''`),
   пропустить через `sanitizeHtml()`, пустая строка → `null`.
2. Внутри `<footer id="forum-about">`, перед `<Container>` со строкой
   копирайта, при непустом `sanitizedFooter` рендерить `<div
   className="forum-custom-footer" dangerouslySetInnerHTML={{ __html:
   sanitizedFooter }} />`.
3. Стили: только семантический класс, цвета и отступы — через переменные
   темы. Новых импортов `react-bootstrap`, инлайн-стилей и Bootstrap-
   утилит в новом коде не добавлять (правила темизации).
4. Копирайт и `ScrollButtons` не трогать.

## 5. Проверки

- `npm run build` и `npm test` — зелёные.
- Футер с обычным HTML (ссылка, картинка, мелкий текст) отображается на
  главной и на странице топика, над копирайтом; копирайт на месте.
- `<script>`, `on*`-атрибуты, `iframe`, `javascript:`-ссылки в сохранённом
  HTML не исполняются и не попадают в DOM.
- Переключение языка EN/RU меняет футер; при пустом значении на текущем
  языке показывается `en`-вариант; при обоих пустых футер выглядит ровно
  как до изменения.
- Сохранение пустого значения убирает кастомный блок полностью.
- Предпросмотр в админке совпадает с тем, что видит пользователь.

## 6. Вне скоупа

- Переопределение футера на уровне дизайна (`activeDesign`).
- Отдельный футер для разных страниц или категорий.
- Визуальный редактор HTML в админке (только текстовое поле + предпросмотр).
