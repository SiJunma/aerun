# Бриф: разложить концепт поиска по форуму в пошаговый план спринтов

Ветка: `main`.
Контекст: согласованный концепт `markdowns/CONCEPT_Search_Page.md` (версия 2.0) — страница расширенного поиска `/search` по форуму. Поиска в проекте сейчас нет вообще: ни FTS5, ни хендлера, ни эндпоинта, ни страницы. Свежая квота Gemini в Antigravity — на эту работу.

## Задача

Не писать код. Разложить концепт (раздел 9, этапы 1–4) в детальный пошаговый план спринтов для исполнителя: что делать, в каком порядке, что проверять после каждого спринта. План — это пошаговая инструкция, а не отчёт о том, какие правила где поменялись.

## Что строить (опора на концепт)

- Страница `/search`: форма в стиле MyBB — ключевые слова с `AND`/`OR`/`NOT`, фразами в кавычках и префиксом `*`; автор (аккаунт, маска персонажа, гость, `AuthorRef`); раздел; область поиска (текст и заголовки / только текст / только заголовки); сортировка (дата, релевантность BM25, автор, заголовок, раздел), порядок, формат выдачи (`Posts` / `Topics`).
- История до 5 запросов в `localStorage` (`aerun_search_history`), чипы с префиллом и очисткой.
- Сниппеты ~200–300 символов с подсветкой `<mark class="search-highlight">`, очистка от тяжёлого BBCode.
- Пагинация готовым `ForumPagination.jsx`, параметры поиска — в query URL.
- «Поиск в теме»: кнопка в `TopicPage.jsx`, переход `/search?topic_id=...&as=posts`, плашка с названием темы; deep-link `/topic/:id?post=:postId&highlight=...` с подсветкой целевого поста.
- Ссылка «Поиск» в навбаре (`allowGuest: true`); в профиле отдельный поиск не выносится — таб «Сообщения» дополняется переключателем «Сообщения автора / Темы автора».
- Бэкенд: SQLite FTS5 (`posts_fts`, токенизатор `unicode61 remove_diacritics 2` — кириллица case-insensitive), миграция `17700000xx_posts_search_fts5.go`, синхронизация в тех же транзакциях, что создание/правка/hard-delete поста, одноразовый бэкфилл опубликованных постов; хендлер `searchHandler` (`backend/internal/platform/pocketbase/search.go`); API `GET /api/aerun/search` по контракту из раздела 6 концепта (`q`, `author`, `exact_author`, `category_id`, `topic_id`, `in`, `sort`, `order`, `as`, `page`, `limit` с clamp 1..50).
- Стек: Go 1.27 + PocketBase v0.40.4 + SQLite (FTS5) + React 19 + Lucide-react. React-Bootstrap в новом коде не используется.

## Безопасность — не упрощать при планировании

- RBAC: выдача только по категориям из `canViewCategory`, темам из `canViewTopic`; закрытые разделы не попадают даже в список выбора.
- Черновики (`is_draft = true`) и отложенные scheduled-посты строго исключаются.
- Тег `[hide]` — zero leakage (раздел 5.3 концепта): если совпадение только внутри недоступного зрителю хайда, пост не возвращается вообще — ни в `items`, ни в `total`; закрытый текст вырезается из сниппетов. Для обладателей `PermBypassHideTags` — полный поиск без ограничений.

## Правила темизации (раздел 8 концепта) — обязательны с первого дня

Поиск — новый код, поэтому он сразу следует правилам темизации, а не стилю, из которого мигрируются старые страницы:

1. Без инлайн-стилей (`style={...}`) в новых компонентах поиска.
2. Без Bootstrap-утилит (`d-none`, `d-flex`, `p-1`, `mb-3`, `text-muted`, `border-0` и подобные) — свои классы из `SearchPage.css`.
3. Без новых импортов react-bootstrap — кнопки, селекты, модалки через общие компоненты проекта.
4. Цвета — только через переменные темы из `src/styles/theme-variables.css`, hex напрямую запрещён. Новые токены — только цвета, во все три темы (light / dark / neutral). Новых геометрических токенов не создавать.
5. Подсветка найденного (`<mark class="search-highlight">`, выделение целевого поста при deep-link) — через новые токены (например, `--search-highlight-bg`, `--search-highlight-color`), заданные во всех трёх темах, без захардкоженного жёлтого.
6. Новые стили — в `SearchPage.css`, а не в `src/index.css` и не в общие файлы. Переиспользовать уже мигрированные компоненты и их CSS (`TopicRow`, `ForumPagination`, карточка поста), а не изобретать вторую систему карточек.
7. Проверка в трёх темах перед сдачей: форма, результаты, сниппеты с подсветкой, чипы истории, плашка «Поиск в теме».

## Как разбить на спринты

Этапы из раздела 9 концепта — основа, но их надо разбить на спринты такого размера, чтобы каждый сдавался отдельно и проверялся:

1. Этап 1 (бэкенд: миграция FTS5, бэкфилл, хендлер, хайды, RBAC, тесты) — разбить минимум на два спринта: сначала миграция + бэкфилл + базовый хендлер без хайдов, потом хайды + RBAC + тесты на кириллицу, `[hide]`, `AuthorRef`, изоляцию разделов.
2. Этап 2 (клиентский API `src/api/search.js`) — маленький спринт, можно совместить с началом этапа 3, но с отдельной проверкой.
3. Этап 3 (страница поиска) — разбить: форма + история, потом карточки результатов + подсветка + пагинация.
4. Этап 4 (интеграция: маршрут, навбар, «Поиск в теме», `?highlight=`) — отдельным спринтом в конце.
5. После каждого спринта — проверки: `npm run build` зелёный, `npm test` зелёный, греп-проверки (нет `style={`, нет Bootstrap-утилит, нет новых импортов react-bootstrap, нет hex-цветов в новых CSS), визуальная проверка в трёх темах для UI-спринтов.

## Не делать

- Не писать код и не коммитить — только план спринтов.
- Не трогать ветку `feature/theming` — там идёт отдельная работа (Sprint G, визуальные правки RichEditor), поиск делается в `main`.
- Не менять концепт `CONCEPT_Search_Page.md`.
- Не мержить ветки — мержи решает пользователь.

Дока остаётся environment-neutral: никаких локальных путей, зеркал и контекста этой машины.
