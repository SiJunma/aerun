## F-01. При смене страницы показывать скелетон, а не старую страницу (аудит §2)

- **Проблема:** при переходе на другую страницу темы на экране остаётся старая страница, пока идёт запрос; скелетон показывается только когда постов нет совсем.
- **Решение:** во время загрузки новой страницы показывать скелетон; старую страницу как актуальную не держать.
- **Доделка (проверка кода, 2026-11-18):** скелетон-карточки при смене страницы уже показываются (`TopicPage.jsx`, ветка `isPageLoading`), но старые посты остаются на экране под ними: `posts.map` рендерится безусловно, а `useTopicPosts` не очищает посты в начале не-тихой загрузки. Доделать: при не-тихой загрузке новой страницы старые посты не рендерить, пока идёт запрос (гейтить рендер списка по `isPageLoading` или очищать посты в начале загрузки). Тихую перезагрузку не трогать: при приходе чужого поста на той же странице текущая страница остаётся на экране без вспышки скелетона.
- **Приёмка:** переход между страницами темы (включая «Last») никогда не показывает посты другой страницы; во время загрузки виден только скелетон.

## F-02. У гостя нет кнопки профиля, ведущей на `/profile/undefined` (аудит §6a)

- **Проблема:** в футере карточки поста ссылка «Profile» рендерится безусловно; у гостя нет `user_id`, ссылка ведёт на `/profile/undefined`.
- **Решение:** гейтить ссылку профиля наличием `user_id` у автора — только аккаунты, как уже сделано для ссылки ЛС. Десктопную ссылку профиля в сайдбаре проверить тем же паттерном.
- **Приёмка:** у гостевого поста нет ссылки «Profile» (мобильная и десктопная версии); у поста аккаунта ссылка на месте; в приложении нигде не возникает `/profile/undefined`.

## F-03. Отступ книзу у контента поста не зависит от подписи и репутации (аудит §6b)

- **Проблема:** у гостевого поста (без подписи и репутации) контент упирается в разделитель футера; видимый отступ дают только условные блоки подписи и репутации.
- **Решение:** задать отступ снизу на `.post-content` (или `.post-footer`), а не заимствовать его у условных блоков.
- **Приёмка:** у гостевого поста между контентом и футером есть воздух, как у поста аккаунта; вид поста аккаунта не изменился.

## F-04. Скролл к последнему / непрочитанному — нативный механизм (аудит §7)

- **Проблема:** переход к последнему посту останавливается на 1–2 поста раньше цели (плавающий баг, зависит от тайминга загрузки картинок).
- **Решение:** убрать ручную арифметику (`useTopicJumpScroll.js`: `NAVBAR_OFFSET = 85`, `getBoundingClientRect()`, `window.scrollTo`). Скроллить одним нативным вызовом `el.scrollIntoView({ block: 'start' })` — браузер сам учтёт `scroll-margin-top: 85px` из CSS. Скроллить только по свежей странице (`isPageLoading === false`, `loadedPageRef === currentPage`).
- **Не делать:** повторные замеры, `ResizeObserver`, `document.fonts.ready`, докрутку.
- **Приёмка:** `?goLast=1` и переход к первому непрочитанному приземляются точно на целевой пост — в теме с картинками в постах выше цели, и с холодной загрузки, и из уже открытой темы. Недоскролла на 1–2 поста нет.

## F-05. Скелетоны — через живые компоненты + дебаг-роут (аудит §8)

- **Проблема:** скелетон поста не совпадает с настоящим постом: авторская колонка без ширины (настоящая — 200px), аватар 80px вместо 150px. Полностраничный скелетон темы — голый `<Skeleton />` без размеров.
- **Решение (полный спек — в аудите §8, раздел «План-спек»):**
  1. У каждого компонента — скелетон-ветка через проп `skeleton`: та же оболочка и классы, контент заменён полосками. Предзаполненный текст — `visibility: hidden` (не `display: none`). Без data-хуков, без `id`, без живых ссылок/кнопок (`inert`, `aria-hidden`).
  2. По порядку: пост темы (`TopicPostCard`) и полностраничный скелетон темы → главная → категория (`TopicRow`, шапка категории) → профиль → участники (строки в той же таблице).
  3. Дебаг-роут `/_debug/skeletons` в приложении, только для root-админа; рендерит все скелетоны через живые компоненты, с контролами количества строк/постов, темы и viewport. Роут не в навигации, гостям и обычным участникам недоступен.
  4. Удалить мёртвые классы `.topic-skeleton*` и прочие старые скелетон-классы после перевода.
- **Доделка (проверка кода, 2026-11-18):** готовы скелетон-ветки поста темы (`TopicPostCard`, проп `skeleton`) и строки топика (`TopicRow`), полностраничный скелетон темы и дебаг-роут с контролами. Осталось перевести на живые скелетон-ветки:
  1. Главная (`MainPage.jsx`): строки разделов до сих пор на старых классах (`forum-skeleton-group`, `skeleton-forum-item`).
  2. Категория (`CategoryPage.jsx`): инлайн-скелетон строк топиков и скелетоны шапки категории.
  3. Профиль (`ProfilePage.jsx`): скелетоны шапки и вкладки About.
  4. Участники (`MembersPage.jsx`): одна полоска вместо строк в той же таблице.
  5. Дебаг-страница (`SkeletonDebugPage.jsx`): заменить инлайн-полоски для категории/профиля/участников на живые скелетон-ветки, как только они появятся.
  6. Гейт дебаг-роута: сейчас роут открыт любому админу (`requireAdmin` / `ADMIN_ACCESS`), а по спеку — только root-админу. Ужесточить гейт до root-админа.
- **Приёмка:** на 768/1024/1440px скелетон поста совпадает с настоящим постом по ширине колонки (200px), аватару (150px) и отступам; высота карточки не меняется при замене скелетона настоящим постом; дебаг-роут не делает запросов к API и недоступен гостю и обычному участнику.
